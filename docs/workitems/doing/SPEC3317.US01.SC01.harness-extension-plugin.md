## Outcome

The TinyTools server is delivered the way Coder and Builder are: a backend plugin package and a frontend contribution that a Harness deployment can compose, instead of a bespoke application only this repository can run.

## Acceptance criteria

- [ ] UAC01: Backend and frontend contributions are separated into packages with stable ids, versions and a plugin descriptor, mirroring the Coder and Builder packaging shape.
- [ ] UAC02: The backend package registers the template DbContext and its endpoints without the host compiling repository source.
- [ ] UAC03: The frontend package contributes the Templates route, page and store through the plugin composition surface rather than a hard project reference.
- [ ] UAC04: A composed host runs the packages, and a recorded session lists the contributed route and serves the Templates page.
- [ ] UAC05: Package hashes, image or deployment identity and the verification URLs are recorded in evidence, and withdrawal of the package removes the route.
- [ ] UAC06: Each package carries its own `lowlandtech/plugin.json` for the plugins schema version 1, packed as `None ... PackagePath="lowlandtech\"` and embedded as a resource under `lowlandtech/plugin.json`: the api package declares `target: backend` with empty routes and contributions, the app package declares `target: blazor` with the templates route, its page contribution and its client assets.
- [ ] UAC07: The app package declares its CSS and JS through the Plugins lane client-asset contract (`assets.stylesheets`, `assets.scripts`) with paths under `_content/<PackageId>/`, and it sets `StaticWebAssetBasePath` to that same root so every declared path resolves.
- [ ] UAC08: Every declared asset passes `PluginClientAssetPaths.TryResolve` for its package id and kind; a declared path that is host-relative, absolute, traversing, query-bearing, fragment-bearing or of the wrong extension is refused with its named reason instead of being served.
- [ ] UAC09: The plugin packages reference `LowlandTech.Plugins.Domain` for the manifest and surface contract rather than declaring a second manifest model in this repository.
- [ ] UAC10: The backend package exposes the template API only at the resource-based `/api/templates` route from M6-009; no public API path contains the Tinytools plugin or package identity.

## Refinement decisions and staged plan (lane-owned, 2026-10-30)

The refinement gap asked the owner to confirm the manifest schema version, the package ids and
versions, and the Harness target, and to settle whether `src/app` changes SDK or a new frontend
package is created. Decisions:

| Question | Decision |
|---|---|
| Manifest schema | **version 1**, one `lowlandtech/plugin.json` per package, packed as `None ... PackagePath="lowlandtech\"` and embedded as a resource so a host can read it without the package on disk. |
| Package ids | `LowlandTech.TinyTools.Api` (`target: backend`) and `LowlandTech.TinyTools.App` (`target: blazor`), matching the assembly names already in the solution so the change stays structural rather than renaming. |
| Versions | derived from the single authority in `Directory.Build.props` (M5-004), never declared per package. |
| Frontend SDK | the app package **changes SDK to `Microsoft.NET.Sdk.Razor`** instead of adding a fourth project: it already owns the page, the store and the client assets, and a separate package would duplicate the composition surface the frontend project already defines. |
| Asset root | `StaticWebAssetBasePath` = `_content/LowlandTech.TinyTools.App`, so every path declared in `assets.stylesheets` / `assets.scripts` resolves under that root. |
| Contract source | `LowlandTech.Plugins.Domain` supplies `PluginManifest`, `PluginClientAssetPaths`, `PluginClientAssetKind` and the refusal type; this repository declares **no** second manifest model. |
| API surface | unchanged from M6-009: `/api/templates` only, with no Tinytools identity in any public path. |

Verified prerequisites, so this is not speculation:

- `LowlandTech.Plugins.Domain` is present in the workspace feed (`2026.10.1-20261030063217803391801`) and exports exactly the types the criteria name: `PluginClientAssetPaths`, `PluginClientAssetKind`, `PluginClientAssetRefusal`, `PluginManifest`, `PluginClientAssets`, `PluginClientAssetDeclarations`.
- `LowlandTech.Plugins` (the loader) is present too, depending on `Plugins.Domain`.
- Neither `src/app` nor `src/api` has a `lowlandtech/plugin.json` today, and both are plain hosts (`Microsoft.NET.Sdk` and `Microsoft.NET.Sdk.Web`), so UAC06-UAC10 are greenfield inside this repository.

### Layout correction (2026-10-30, discovered before implementing)

The pickup packet assumes `src/app` must change SDK and that `src/api` is the backend package.
The repository is already further along than that description, and starting from it would have
produced the wrong change:

| Project | Reality | Consequence |
|---|---|---|
| `src/frontend` | `Microsoft.NET.Sdk.Razor`, `IsPackable=true`, `PackageId=LowlandTech.TinyTools.Frontend` | this **is** the blazor plugin package; it needs the manifest, `StaticWebAssetBasePath` and its assets declared, not a new project |
| `src/app` | `Microsoft.NET.Sdk.Web`, `IsPackable=false`, the development host | stays the development entry point; no SDK switch |
| `src/api` | `Microsoft.NET.Sdk.Web`, `IsPackable=false`, the development host | the backend plugin needs a packable library (or a packable api project); there is no backend library today |
| `src/app/wwwroot/app.css` | the built Tailwind stylesheet lives in the **host** | for UAC07 to declare a stylesheet under `_content/`, the stylesheet must move into the packable frontend package |

So stage 1 concretely means: move the built stylesheet into `src/frontend/wwwroot`, add
`StaticWebAssetBasePath=_content/LowlandTech.TinyTools.Frontend`, declare the two client assets,
add `lowlandtech/plugin.json` to the frontend and to whichever project becomes the backend
package, reference `LowlandTech.Plugins.Domain` in both, and add facts over
`PluginClientAssetPaths.TryResolve` for the declared and refused paths. The package id stays
`LowlandTech.TinyTools.Frontend` rather than the `...App` name guessed in the decision table
above; that row is superseded here.

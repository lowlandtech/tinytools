## Outcome

The shared workitem mirror can reconcile this repository's issues without replacing the evidence text
they already carry, so `--verify-only` stops reporting drift that nobody intends to fix by rewriting
47 issues.

## Problem

`eng/workitems.py --apply` regenerates each managed issue from its source, and `--verify-only` fails
while any issue differs. This repository's issues predate the managed convention, so all 47 differ.
Measured at SPEC3318 (delivery record) with a throwaway patched copy of the tool:

- `--dry-run` -> `ok=true items=47`, every action `update`, **zero create**, so identity is correct.
- `--dry-run --preserve-body` -> still `update=47`, so the body is not the only difference.
- Comparing `#10`: the tool wants `SPEC3300-US03-SC02: Preserve comparison operator precedence`, the
  issue is titled `Operator precedence bug in TinyTemplateEngine condition evaluation`; state and
  label sets differ too.

Applying the global plan would therefore rename and relabel 47 issues as well as replace their bodies.
Neither is authorised by any workitem.

## Contract (lane-owned proposal, for the tooling owner)

| Flag | Behaviour |
|---|---|
| `--preserve-body` | keep an existing body that already carries `<!-- workitem:<scope> -->`; ignore generated body text |
| `--preserve-title` | keep an existing issue title when the marker is present |
| `--preserve-state` | keep an existing open/closed state, reporting a mismatch instead of correcting it |
| verification | with all three, `--verify-only` means "the marker resolves and the scope is mirrored", which is the only claim this lane can support |

Implementing this is a workspace-tooling change (`D:/lowlandtech/eng/workitems.py`), not a Tinytools
source change, so this item records the scope and the evidence rather than editing the shared tool.

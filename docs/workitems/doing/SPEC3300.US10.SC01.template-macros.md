## Refinement decisions (lane-owned, resolved 2026-10-30)

| Question | Decision |
|---|---|
| Definition syntax | `@macro name(p1, p2) { body }` inline in template source. The body is the balanced brace block after the parameter list, so it may contain braces and any renderer construct. Definitions are removed from the output. |
| Invocation | `@name(arg1, arg2)`; arguments are comma-separated, a quoted argument becomes a literal string, anything else is resolved as an expression against the caller's context. |
| Return semantics | A call renders its body with the arguments bound as context values on a child context, so the body keeps the full renderer - interpolation, `@if`, `@foreach` - and two calls with different arguments share no state. |
| Arity errors | `InvalidOperationException("Macro 'name' expects N argument(s) but received M.")`. |
| Unknown macro | `InvalidOperationException("Macro 'name' is not defined in this template.")`. |
| Recursion policy | Definitions are visible to nested bodies, and expansion is cut off at 32 nested expansions with `InvalidOperationException("Macro recursion limit exceeded (32 nested expansions).")`, so a self-invoking macro terminates. |
| Scope | A call is only treated as a macro call when the same template declares at least one macro, so ordinary text that looks like `@name(...)` is untouched. |

## Coordinator refinement — M3 current milestone

### Coordinator contract decision

The coordinator fixes this in-scope language contract so the lane has one bounded target:

| Surface | Contract |
|---|---|
| Definition | `@macro name(param1, param2) {` opens a named block; a matching `}` closes it. Definitions are collected before body rendering and produce no output. Macro names and parameter names use ASCII letters/digits/underscore, start with a letter, and compare ordinally. |
| Invocation | `@name(arg1, arg2)` invokes a defined macro. Arguments are comma-separated Tinytools expressions resolved once in the caller context, left to right. Quoted strings, numbers, booleans, null and existing context paths are accepted; nested calls/commas inside quoted strings are outside this scope. |
| Parameters/context | Each call gets a child context inheriting caller values and registered synchronous services. Parameters are bound by name and visible as `${parameter}` in the macro body. Caller context is never mutated by parameter binding; separate calls do not share bindings. |
| Errors | Unknown macro and wrong arity raise `InvalidOperationException` naming the macro and, for arity, expected and actual counts. No partial output is returned. |
| Recursion | Re-entering a macro is refused with `InvalidOperationException` containing `Macro recursion limit exceeded` and the active macro chain. The maximum active macro depth is 32; no general-purpose code execution is introduced. |
| Body composition | Existing interpolation and control-flow syntax execute in the child context. Body whitespace follows the existing renderer's line normalization; a single-line definition preserves its body text exactly. |

The implementation remains solely in Tinytools' parser/renderer. No nested macro calls inside an argument, filesystem loading or macro package is included.

## Outcome

Exactly one workflow publishes each feed, and continuous integration fails on the conditions the project claims to enforce instead of reporting on them.

## Acceptance criteria

- [ ] UAC01: Only one workflow can publish the NuGet package to a given feed; the unreachable `pack` job in `.github/workflows/main.yml` is removed or given a real trigger.
- [ ] UAC02: API-key secret names agree across the retained workflows and are documented where an operator can find them.
- [ ] UAC03: The known-vulnerable restores (`NCalc.Core`/`NCalcSync` and `Microsoft.Build.Tasks.Git`) are upgraded, or suppressed with a dated recorded reason.
- [ ] UAC04: Coverage either fails the build below a recorded threshold or the non-enforcing upload is removed.
- [ ] UAC05: The SDK matrix matches the project targets: one pinned SDK builds `net8.0`, `net9.0` and `net10.0`, and no job claims a framework it cannot build.

## Scheme decision and progress (lane-owned, 2026-10-30)

**Decision: one pipeline, two tiers of gate.** `main.yml` keeps a single workflow, and inside
it the gates are split by what they need:

1. **Verifiable gates** - everything this repository can prove without the workspace feed:
   the single version authority (every project resolves the same `Version`, the readme badge
   and the changelog heading agree), the behavior-test layout grammar, and a library pack that
   must produce `LowlandTech.TinyTools.<declared version>.nupkg`. This job **must stay green**.
2. **Build & Test matrix** - the full `ubuntu/windows/macos × 8.0.x/10.0.x` matrix. It cannot
   pass until `LowlandTech.Components` is published to a feed a hosted runner can reach, and
   the workflow now says so in place instead of leaving six identical NU1301 failures to be
   deciphered.

That split is deliberate: a gate that can never be green teaches people to ignore CI, while a
gate that is silently skipped teaches them to trust nothing. The verifiable tier is real, and
the blocked tier names its prerequisite and owner where a reader will look.

## Evidence

### Earlier checkpoint `7b3d190`, run `41095343927`

- **`Verifiable gates`: success** - the first green CI job in the 60 runs checked that day.
  It verified `2026.10.3` across `src/lib`, `src/core` and `src/frontend`, matched the readme
  badge and the `# 2026.10.3` changelog heading, ran the layout check, packed the library and
  asserted the produced file name.
- `Build & Test` (six matrix jobs): `failure`, all at **Restore**, with
  `NU1301: The local source '<runner>/packages' doesn't exist` for `src/app` and `src/test`.
- `Pack NuGet Package`: `skipped`, as it depends on the matrix.

Root cause, verified: `nuget.config` maps `LowlandTech.*` to the workspace feed `../packages`,
and `LowlandTech.Components` is **not on nuget.org** (`dotnet package search` returns no
results). Making the local source optional would trade `NU1301` for `NU1101`, so tinytools
cannot publish that package from this lane.

### Second reading of the workflows (2026-10-31)

The first checkpoint treated the matrix as the only defect. Re-reading all four workflows
found three more, and they were worse than a red matrix because they were invisible:

- **Two publish paths with two spellings of one secret.** `main.yml`'s `pack` job pushed to
  nuget.org with `NUGET_API_KEY`; `tags.yml` pushed with `NUGET_APIKEY`. The `pack` job could
  never run (`main.yml` triggers on branches only, and the job is guarded by a tag condition),
  so the release path was the one that mattered and it read the name nobody had set.
- **A second version authority.** `.gitea/workflows/build.yml` packed with
  `-p:PackageVersion=$(date +'%Y.%m%d').<run_number>`, publishing a CalVer version that no
  other surface knew about. That directly contradicts M5-004, which this lane already closed
  on the rule that `Directory.Build.props` is the only version declaration.
- **SDK matrix mismatched the targets.** The matrix installed `8.0.x` and `10.0.x`, while the
  projects target `netstandard2.1`, `net8.0`, `net9.0` and `net10.0`. An 8.0 SDK cannot build a
  `net10.0` target at all, so half the matrix was guaranteed to fail for a second reason.

### What changed

| Criterion | Change |
|---|---|
| UAC01 | `main.yml`'s unreachable `pack` job is gone. `tags.yml` is the only publisher to nuget.org and GitHub Packages; `.gitea/workflows/build.yml` publishes to the Gitea feed only, so each feed has exactly one writer. |
| UAC02 | nuget.org is `NUGET_API_KEY` on both paths, and the feed/secret map is written at the top of `tags.yml`, where whoever cuts a release is already looking. A standalone `docs/release.md` was tried first and the roadmap gate rejected it (`RMP021`: this repository keeps narrative in workitems, not in `docs/`), so the notes live beside the workflow instead of in a document the repository forbids. |
| UAC03 | `Microsoft.SourceLink.GitHub` 10.0.300 -> **10.0.403**, which pulls `Microsoft.Build.Tasks.Git` 10.0.403 and clears `GHSA-23fw-v26w-5fgq`. `dotnet list package --vulnerable --include-transitive` now reports no vulnerable package for the library on any target. `NCalcSync` 6.3.2 was re-audited in a throwaway project and reports no advisory, so it stays: bumping a test-only dependency to 7.x would be churn without a security reason. |
| UAC04 | Coverage is now a gate. `eng/check-coverage.py` reads the Cobertura reports and fails below the floor; the Linux leg runs it with `--minimum 70`. The non-enforcing Codecov upload is removed. Measured: **77.41%** (3588/4635 lines). |
| UAC05 | One pinned SDK, `10.0.x`, which builds `netstandard2.1`, `net8.0`, `net9.0` and `net10.0` from the reference packs it carries. The matrix is now operating-system only, and the 8.0.x leg that could never build `net10.0` is gone. |

The matrix was also made able to run at all. `src/test` gains a `HostPageSpecs` property
(default `true`): when a hosted runner sets it to `false`, the reference to the App host - the
only project that needs `LowlandTech.Components` - is dropped, together with the three scenario
files that reach it. Everything else restores from public feeds, so CI compiles and runs
**1037 of the 1041 specs** instead of failing at restore and running none.

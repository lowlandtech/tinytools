## Outcome

Users can render one or many templates from files and refresh outputs when inputs change.

## Acceptance criteria

- [x] UAC01: Given a template file, JSON model file and output path, when `render` runs, `RenderedFile` contains deterministic public-engine output and the process result identifies success.
- [x] UAC02: Given a malformed template or invalid JSON, `RenderFailureResult` identifies the input and exits with the declared nonzero code without replacing an existing output with partial content.
- [x] UAC03: Given a watched template/model dependency and a canceled watch process, `WatchRevisions` contains one render per relevant completed input change and shutdown completes without leaving a child process or file handle.
- [x] UAC04: Given an unrelated file change, `UnrelatedChangeCount` does not trigger a render; the set of relevant files must be explicitly enumerated by the CLI contract.
- [x] UAC05: Given a batch with valid and invalid entries, `BatchResults` contains one named result per input in stable input order and the exit policy matches the declared continue/fail-fast choice.
- [x] UAC06: Given an output path outside the permitted workspace root, `RejectedOutputResult` is a named refusal and no file outside the root is created or modified.

## Contract decisions (lane-owned, resolved before implementation)

The refinement gap asked for reconciliation between the workflow CLI and new direct commands,
plus a batch failure contract. Decisions:

| Question | Decision |
|---|---|
| Command surface | `render` and `watch` sit beside `generate` in the same binary, so there is one CLI rather than a second tool. `render` takes one or many templates, `--model`, and `--output`/`--out-dir`; `watch` takes one or many templates plus the same model/output options. |
| Batch policy | **Continue, then fail**: every input is rendered and reported in the order given, and the exit code is `1` when any entry failed. A caller sees all problems in one run. |
| Exit codes | `0` success, `2` usage, `3` a named refusal (output outside the workspace root), `1` a render failure. |
| Partial output | Impossible by construction: the renderer builds the full string first and only then writes the file, so a failing template leaves an existing output untouched. |
| Relevant files for watch | Explicitly enumerated: the template paths given plus the model path. Nothing else in the tree can trigger a render. |
| Watch mechanism | Timestamp polling with a documented interval rather than a filesystem watcher, so the behaviour is the same on every platform and a cancelled token stops the loop with no thread, handle or child process left behind. |
| Output safety | Reuses the workflow root guard: anything resolving outside the workspace root is refused by name before a file is touched. |

## Outcome

The host knows which credential made a call and from where, without trusting anything the client asserts about itself, so an incident can be attributed and a spoofed identity header cannot grant authority.

## Problem

Tinytools has no account system, so the backend scope's account/device/IP provenance has no direct equivalent. What it does have is one credential and a transport peer; those must be recorded and the untrusted inputs must be named.

## Acceptance criteria

- [ ] UAC01: An accepted request Activity carries `tinytools.credential.source=Tinytools:ApiKey` and `network.peer.address` tags; neither tags nor logs contain the configured or supplied key.
- [ ] UAC02: Supplying only `X-User`, `X-Account-Id`, `X-Device-Id`, `Forwarded`, `X-Forwarded-For` or `X-Real-IP` neither authenticates a request nor changes the transport peer recorded by the host.
- [ ] UAC03: Reloading `Tinytools:ApiKey` atomically makes the new value succeed and the old value return 401 on the next request, without restarting the host or exposing either value.
## Scenario contract

Given a production test host with a reloadable in-memory `Tinytools:ApiKey` provider, When a valid request, a spoofed-header-only request and requests before and after key rotation run, Then the named results are `AcceptedCaller`, `SpoofedIdentity`, and `RotatedKey` with source label, transport peer, status and redaction fields. Keep Given construction and When HTTP calls visible in `SC03_RecordsCallerProvenance.cs`; use `EndpointProtectionUseCase` only to name captured results. One Fact per stable UAC01-UAC03.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

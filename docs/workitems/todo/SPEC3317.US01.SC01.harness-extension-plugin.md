## Outcome

Tinytools is available as two immutable, package-only Harness contributions: a backend package that owns its service registration and database migration, and a Blazor class-library package that contributes the Templates page, route and declared assets. Harness target pinning and deployed acceptance live in `HARN0013-US01-SC01` in the Harness repository.

## Acceptance criteria

- [ ] UAC01: The backend package has the stable package ID `LowlandTech.TinyTools.Backend` and the frontend package has `LowlandTech.TinyTools.Frontend`; both use the single immutable package version emitted by Tinytools M5-004, with no floating or reused package versions.
- [ ] UAC02: The backend package implements the published `LowlandTech.Plugins.IPlugin` lifecycle from `LowlandTech.Plugins.Domain` `2026.10.1-20261029231326395491648` (SHA-256 `b0e277faa918c754fe8acc796a371fa31647b8e2c87563d331fbb0267fa7e962`). `RegisterAsync` registers Tinytools-owned services and database access from the host configuration; `InstallAsync` uses only the `PluginHostConnection` supplied by the host and records the outcome through its host-owned receipt store. It neither declares an independent connection string nor copies the contract or host lifecycle implementation.
- [ ] UAC03: The backend package registers the imported `TinyToolsDbContext`, the Tinytools template endpoints and the migration implementation without requiring a host `Program.cs` project reference to Tinytools source. The thin `src/api` development host delegates to the package registration surface.
- [ ] UAC04: The frontend package uses `Microsoft.NET.Sdk.Razor`, has package ID `LowlandTech.TinyTools.Frontend`, references `LowlandTech.Plugins.Domain` `2026.10.1-20261029231326395491648` and `LowlandTech.Components` `2026.10.2-202610242`, and contributes the `templates` route, `TemplatesPage`, and imported store through the package composition surface. It has no hard project reference to Harness or a separate API executable.
- [ ] UAC05: The backend package manifest is at `lowlandtech/plugin.json` in the package and assembly, declares `schemaVersion: 1`, `key: tinytools`, `target: backend`, and no client route or asset contribution. The frontend manifest uses `schemaVersion: 3`, `key: tinytools`, `target: blazor`, `installationUnit.requiredCapabilities: ["blazor"]`, its `templates` route/page contribution, and its client-asset declaration. The two manifests are inspected from their packed packages and embedded resources.
- [ ] UAC06: Every frontend asset is declared through `assets.stylesheets` or `assets.scripts`, uses the `_content/LowlandTech.TinyTools.Frontend/` package base path, and passes `PluginClientAssetPaths.TryResolve` for its asset kind. Invalid absolute, host-relative, traversing, query-bearing, fragment-bearing, or wrong-extension declarations are refused with their named reason. Do not declare a script unless the package ships one.
- [ ] UAC07: The package-composition scenario consumes the packed Tinytools packages and exact published plugin contracts from `D:/lowlandtech/packages`; it proves the manifest inspection, backend lifecycle registration, contributed frontend route and page binding without compiling Tinytools repository source into Harness. The test adapter may host the packages but does not replace the deployed acceptance in Harness.
- [ ] UAC08: The package references pin exact immutable versions for `LowlandTech.Plugins.Domain` `2026.10.1-20261029231326395491648` and `LowlandTech.Components` `2026.10.2-202610242` (and their required component contracts); the generated nuspec and dependency closure contain no project references, floating versions, or duplicate manifest/lifecycle contracts.
- [ ] UAC09: Evidence records both package IDs and versions, dependency versions, SHA-256 package hashes, manifest bytes/schema, focused and full suite counts, source commit, and local-feed paths. The item remains open until the Harness-owned `HARN0013-US01-SC01` verifies the published packages in its test deployment.

## Outcome

The TinyTools server is delivered the way Coder and Builder are: a backend plugin package and a frontend contribution that a Harness deployment can compose, instead of a bespoke application only this repository can run.

## Acceptance criteria

- [ ] UAC01: Backend and frontend contributions are separated into packages with stable ids, versions and a plugin descriptor, mirroring the Coder and Builder packaging shape.
- [ ] UAC02: The backend package registers the template DbContext and its endpoints without the host compiling repository source.
- [ ] UAC03: The frontend package contributes the Templates route, page and store through the plugin composition surface rather than a hard project reference.
- [ ] UAC04: A composed host runs the packages, and a recorded session lists the contributed route and serves the Templates page.
- [ ] UAC05: Package hashes, image or deployment identity and the verification URLs are recorded in evidence, and withdrawal of the package removes the route.

Add SPEC3317/US01 with a composition fact that loads the packaged contributions into a host and asserts the route set and the page render. Deployment evidence is separate and recorded with exact identities.

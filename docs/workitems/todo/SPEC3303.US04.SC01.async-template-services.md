## Outcome

A template can invoke an explicitly registered asynchronous service through an asynchronous render path.

## Acceptance criteria

- [ ] UAC01: Given an explicitly registered asynchronous service that completes with a value, when the public asynchronous render path executes a template that invokes it, `AsyncServiceOutput` contains the awaited value and the returned Task is not completed before the service completes.
- [ ] UAC02: Given two asynchronous services in a template with an established evaluation order, `AsyncServiceOrder` reflects the contractually declared order. The lane must specify whether expressions are sequential or concurrent before this criterion is ready.
- [ ] UAC03: Given a registered service that faults with a known exception, when rendering completes, `ServiceFailureResult` is a stable named diagnostic that identifies the service and does not expose a partial output string or exception details beyond the declared contract.
- [ ] UAC04: Given a cancellation token canceled during a pending service call, `CancellationResult` matches the chosen cancellation contract and no later service invocation occurs. Cancellation propagation needs an owner decision before readiness.
- [ ] UAC05: Given existing synchronous `TemplateServiceFunc` and `ITemplateService` registrations, when the existing synchronous `Render` path executes, `SynchronousOutput` remains byte-for-byte compatible with its pre-change result.
- [ ] UAC06: Given an asynchronous-only service invoked from the synchronous render API, `SyncAsyncServiceResult` is the explicit refusal selected by the lane; the sync path must not block on asynchronous work.

## Outcome

Templates can apply the four planned collection transformations with deterministic ordering and grouping.

## Acceptance criteria

- [ ] UAC01: Given a non-null collection and a supported predicate selecting a subset, when the public engine applies `where`, `FilteredSequence` contains exactly matching elements in their source order.
- [ ] UAC02: Given an empty or null collection, `EmptyFilteredSequence` is empty and `NullFilteredSequence` follows the explicitly chosen null rule; the lane must record that rule before readiness.
- [ ] UAC03: Given elements with comparable keys, when `orderby` runs, `OrderedSequence` is ascending by the selected key; elements whose keys compare equal retain their source order.
- [ ] UAC04: Given a null key, a missing key, or a key with incompatible types, `OrderFailureResult` follows a named stable refusal policy. No culture-dependent ordering is permitted unless the lane explicitly records a culture contract.
- [ ] UAC05: Given values with a supported grouping key, `GroupedSequence` contains one group per distinct key in first-seen key order and members in source order.
- [ ] UAC06: Given repeated values, `DistinctSequence` keeps the first occurrence and preserves source order; equality and hash semantics must use the declared comparer contract.
- [ ] UAC07: Given a null collection, `DistinctNullResult` and `GroupedNullResult` follow the same documented null policy as `where` and `orderby`.
- [ ] UAC08: Given a helper name, argument and input that violate its declared grammar, `InvalidHelperResult` identifies the helper and violated argument without silently returning an unchanged value.
- [ ] UAC09: Given a pipeline chaining two of the four transformations, `ChainedSequence` equals the composition in left-to-right pipe order and preserves the element type where the existing helper API allows it.

## Coordinator refinement — M3 current milestone

### Coordinator contract decision

The coordinator fixes a bounded expression grammar for the four already-planned collection helpers. It uses no reflection method calls, arbitrary C#, or culture-dependent comparisons.

| Helper | Contract |
|---|---|
| `where:path<op>literal` | `path` is a dot-separated property path; operators are `==`, `!=`, `<`, `<=`, `>`, `>=`. Literals are quoted strings, invariant decimal numbers, `true`, `false`, or `null`. Path lookup supports string-keyed dictionaries (ordinal-ignore-case keys) and public readable instance properties. The result preserves source order. |
| `orderby:path[:asc|desc]` | Sorts by the same path rules; ascending is default. Ordering is stable. Strings use ordinal comparison, numbers use invariant numeric comparison, booleans use false-before-true; null sorts first ascending and last descending. Missing paths or incomparable values throw `ArgumentException` naming the helper/path. |
| `groupby:path` | Returns `IEnumerable<IGrouping<object?, object?>>`; groups appear in first-seen key order and each group's members retain source order. Keys use the same equality rules as `distinct`. |
| `distinct` | Uses `object.Equals`/`GetHashCode`, retains the first equal element and preserves source order. No custom comparer parameter is added. |
| Null/empty input | Null and empty enumerables produce empty sequences for all four helpers. Strings are scalar values and are not treated as collections. |
| Invalid expressions | Missing path, malformed operator/literal, unsupported value type or incompatible comparison throws `ArgumentException` with helper and input; unknown helper behavior is untouched. |

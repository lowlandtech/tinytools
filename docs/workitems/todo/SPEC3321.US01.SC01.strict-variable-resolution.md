## Outcome

A template rendered in strict mode refuses an unknown variable instead of emitting an empty string.

## Problem

A missing context key currently logs a warning and resolves to `""`, so `Hello ${Name}` renders `Hello ` and the caller ships plausible but wrong output. For a tool whose value is deterministic generation, a silent empty string is the worst failure mode.

## Contract decisions (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Opt-in or default | opt-in through `TemplateRenderOptions { StrictVariables = true }`; the default stays lenient so existing templates keep rendering |
| Failure surface | `TemplateResolutionException` naming the expression, the missing segment and its line/column, derived from the same locating logic `ValidateSyntax` already uses |
| Scope | unknown context keys and unknown pipe helpers both fail; a known key with a null value still renders empty unless `FailOnNull` is set |
| Diagnostic parity | the exception carries a stable code (`TR001` unknown key, `TR002` unknown helper) so a host can report it without parsing text |

## Acceptance criteria

- [ ] UAC01: A missing key under strict mode raises `TemplateResolutionException` naming the expression and the missing segment, and no output is produced.
- [ ] UAC02: The same template under the default mode still renders, with the unknown segment resolving to an empty string.
- [ ] UAC03: An unknown pipe helper under strict mode raises the exception with code `TR002`; under the default mode the value passes through unchanged.
- [ ] UAC04: A known key holding null renders empty under strict mode unless `FailOnNull` is set, in which case it raises with code `TR003`.
- [ ] UAC05: The exception reports a one-based line and column that point at the offending `${...}` token.
- [ ] UAC06: Existing behavior scenarios keep passing with strict mode off, proving the default is unchanged.

## Scenario contract

Scenario `src/test/SPEC3321.Strict/US01.UnknownVariables/SC01_RefusesUnknownVariables.cs` renders the same template twice, once per mode, and asserts the captured exception code, message, line and column alongside the lenient output.

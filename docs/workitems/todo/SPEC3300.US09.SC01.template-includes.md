## Outcome

Templates can reuse nested fragments with explicit context isolation.

## Acceptance criteria

- [ ] UAC01: Given a registered fragment source and a parent template that names it, when the public `TinyTemplateEngine.Render` renders the parent, the captured `IncludedText` is exactly the fragment output at the include position.
- [ ] UAC02: Given a parent and two fragments where one names the other, when the parent is rendered, `NestedText` contains each fragment once in declaration order and surrounding parent text remains in place.
- [ ] UAC03: Given the same registered fragment names with different caller data, when two parent renders execute, `CallerOneText` and `CallerTwoText` reflect the data explicitly passed to each render; neither render observes values captured from the other call. The implementation contract must state whether fragment context is shared or projected before this criterion is ready.
- [ ] UAC04: Given a missing fragment reference, when the public render executes, `MissingFragmentResult` names the unresolved fragment and no partial string is returned.
- [ ] UAC05: Given direct and indirect recursive references, when validation or rendering executes, `CycleResult` is a stable named refusal and no unbounded recursion occurs. The owner must choose the diagnostic surface and cycle policy before this criterion is ready.
- [ ] UAC06: Given an empty fragment and a fragment containing newlines, when the parent renders, `EmptyFragmentText` and `MultilineFragmentText` preserve the engine's existing LF normalization and block line-boundary contract.

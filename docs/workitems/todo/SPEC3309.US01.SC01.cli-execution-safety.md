## Outcome

The `generate` command cannot hang on child-process output, states and enforces its command trust policy, and both the CLI and `WorkflowRunner` are covered by executable tests instead of being shipped unverified.

## Acceptance criteria

- [ ] UAC01: A command step whose child process writes more than one pipe buffer to standard output and standard error concurrently completes; both streams are read concurrently.
- [ ] UAC02: The command policy is documented and enforced before a process starts: a refused command exits non-zero with a message naming the refused value.
- [ ] UAC03: A failing command step reports the child exit code and captured standard error, and the CLI exits non-zero instead of reporting success.
- [ ] UAC04: Template steps are covered for first write, unchanged idempotent rerun, `forEach` producing one output per item, and a refusal when an output path escapes the workflow root.
- [ ] UAC05: The CLI test project is part of `tinytools.slnx` and runs under the delivery gate.

## Scenario contract

Add SPEC3309/US01 with process-level facts over a temporary workflow directory. Given writes a workflow file and its model, When invokes the CLI entry point or the runner, Then asserts files, exit codes and messages. Assert content and exit status, never elapsed time.

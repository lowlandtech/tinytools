## Outcome

Templates can define reusable parameterized blocks and render their returned text.

## Acceptance criteria

- [ ] UAC01: Given a template defining one macro with declared parameters and a call supplying those parameters, when the public `TinyTemplateEngine.Render` executes, `MacroOutput` equals the exact returned text with each parameter substituted at its declared use sites.
- [ ] UAC02: Given two calls to the same macro with different argument values in one render, when the template executes, `FirstCallOutput` and `SecondCallOutput` contain their own values and do not share mutable call state.
- [ ] UAC03: Given a call with too few arguments, `TooFewArgumentsResult` names the macro and expected/actual arity.
- [ ] UAC04: Given a call with too many arguments, `TooManyArgumentsResult` names the macro and expected/actual arity.
- [ ] UAC05: Given a call to an undefined macro, `UnknownMacroResult` names the requested macro.
- [ ] UAC06: Given a macro body with ordinary interpolation and control flow already supported by the engine, when invoked, `ComposedMacroOutput` preserves those existing renderer results and line boundaries.
- [ ] UAC07: Given direct and indirect self-invocation, `RecursionResult` is a stable named refusal and rendering terminates. Recursion limits and the diagnostic surface require an owner decision before readiness.

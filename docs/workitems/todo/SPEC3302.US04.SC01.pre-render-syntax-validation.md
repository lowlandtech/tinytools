## Outcome

Callers can explicitly validate supported engine-template syntax before rendering through `ITemplateEngine.ValidateSyntax(string)`, receiving a `TemplateSyntaxValidationResult` that distinguishes valid input from syntax failure without reusing the existing example-output `TemplateValidationResult`.

## Acceptance criteria

- [ ] UAC01: Valid supported control-flow and interpolation syntax returns `TemplateSyntaxValidationResult.IsValid == true` with no diagnostics and retains the existing render output.
- [ ] UAC02: Malformed control-flow or interpolation syntax returns `IsValid == false` with at least one stable diagnostic code and message; source coordinates are added by dependent scope SPEC3300-US08-SC01.
- [ ] UAC03: Validation is an explicit parse/validate operation; it does not invoke render helpers or change render behavior implicitly.
- [ ] UAC04: The existing `TemplateValidationResult` for comparing example output remains unchanged and distinct from syntax validation.

## Scenario contract

Create US04 for engine-level validation, separate from the existing `ITemplate.Validate` example-output contract. Add `ValidateSyntax(string)` to `ITemplateEngine` and a `TemplateSyntaxValidationResult` with `IsValid` and diagnostics containing stable code/message fields; reserve line/column semantics for dependent M2-003. Tests should verify validation only and should not make malformed `Render` behavior an implicit API contract.

## Outcome

A `src/api` host serves the template contract over HTTP and renders through this repository's own engine, so the server and the package cannot drift apart.

## Acceptance criteria

- [ ] UAC01: `src/api` targets `net10.0` and exposes `/api/tinytools/templates` for list, get, create, update and delete, plus `POST /render` and `POST /versions/{id}/validate`.
- [ ] UAC02: Rendering and validation call `LowlandTech.TinyTools` through an `ITemplateExecutor` implementation in this repository; no copy of the engine or its expression parser is introduced.
- [ ] UAC03: Persistence uses a `TinyToolsDbContext` with schema `tinytools` and the imported entity model; a connection string containing `Host=` selects Npgsql and anything else selects SQLite, which is created rather than migrated.
- [ ] UAC04: Exactly one authorization policy is declared and applied to the route group; its development default and its non-loopback requirement are documented in one place.
- [ ] UAC05: An OpenAPI document lists the seven operations with their route names.
- [ ] UAC06: An integration fact drives create, list, render, validate and delete through the real HTTP pipeline against a SQLite database, without stubbing the endpoints.

## Scenario contract

Add SPEC3315/US02 with a `WebApplicationFactory`-based scenario that owns one SQLite database per run. Given seeds two templates through the API; When issues the request under test; Then asserts status, payload shape and the rendered output.

## Outcome

Variable resolution is measurably faster and allocates less memory for a fixed representative workload, with byte-for-byte identical rendered output and the existing roadmap target of at least 20% median throughput improvement.

## Acceptance criteria

- [ ] UAC01: The same dependency-free Release benchmark workload records the baseline and changed medians, runtime/SDK, OS, CPU, warmup, iterations and allocated bytes per operation.
- [ ] UAC02: Across five independent Release process runs on the same machine and SDK, the changed median throughput is at least 20% higher than the baseline median.
- [ ] UAC03: Allocated bytes per operation are lower after the change and the output for every benchmark input is byte-for-byte identical to baseline.
- [ ] UAC04: The optimization passes named behavior cases for nested model-path resolution, chained pipe helpers and null-coalescing, including null and populated inputs.

## Fixed benchmark workload

Use a dependency-free console benchmark project at src/benchmarks/VariableResolution. Each process performs 2,000 warmup and 20,000 measured ITemplateEngine.ResolveVariables operations over the same fixed context and template:

Customer: ${Context.Model.Customer.Address.City | upper}; Owner: ${Context.Owner | trim | upper}; Alias: ${Context.Alias ?? "anonymous"}

Given model Customer.Address.City = "Amsterdam", Owner = " Ada ", and Alias absent or set to "ops", expected outputs are respectively "Customer: AMSTERDAM; Owner: ADA; Alias: anonymous" and "Customer: AMSTERDAM; Owner: ADA; Alias: ops". Each of five fresh Release process runs emits one machine-readable row with elapsed ticks, operation count, throughput and GC.GetAllocatedBytesForCurrentThread delta per operation. No wall-clock threshold is placed in the unit tests.

## Scenario contract

Use case: a library caller resolves a fixed template against a nested model and optional context values. New behavior scenarios keep ExecutionContext construction, model setup, ResolveVariables call and captured output visible in scenario source; case results assert the actual output and must not hide Given/When in a UseCase or benchmark helper.

| Named result case | Given / When kept visible in scenario source | Observable result |
|---|---|---|
| NestedModel | A model with Customer.Address.City set to Amsterdam / resolve the fixed template | The output contains Amsterdam in the nested field; UAC04. |
| PipeChain | Owner is set to a value with surrounding spaces / resolve the fixed template | The output contains ADA after trim and upper; UAC04. |
| NullCoalescing | Alias is absent, then populated in a separate case / resolve the fixed template | The absent case uses anonymous and the populated case uses its current value; UAC04. |

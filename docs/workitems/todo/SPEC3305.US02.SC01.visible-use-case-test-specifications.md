## Outcome

Every existing Tinytools test case is represented by a discoverable test specification with a story-level UseCase and named case result, while each scenario keeps its Given and When implementation visible as a practical example of using the library's public API.

## Acceptance criteria

- [ ] UAC01: A complete inventory maps every active test case under `src/test` to a stable specification, user story, scenario and named result case; the before/after discovered case counts reconcile with no silent omissions.
- [ ] UAC02: Each story has an explicit UseCase and typed/cased result model whose named outcomes make the tested success, refusal/failure, boundary or recovery behavior clear.
- [ ] UAC03: Given setup remains visible in the scenario source, including construction/configuration through the public Tinytools API; it is not hidden in a UseCase, fixture or opaque helper.
- [ ] UAC04: When action remains visible in the scenario source and directly shows the public operation under test; it is not moved into a UseCase or hidden behind an invocation helper.
- [ ] UAC05: Each behavior case has its own stable, discoverable assertion identity and checks an observed result; no expected-value-only, placeholder, skipped or empty case counts as coverage.
- [ ] UAC06: Existing meaningful behavior coverage and public-usage examples are preserved or increased; any removed/obsolete case has a cited reason and replacement coverage in the inventory.
- [ ] UAC07: The migrated suite passes on `net8.0`, `net9.0` and `net10.0`, and the scoped test-spec/layout checks report the complete selected inventory with no unexplained skips.

## Scenario contract

Treat each test as executable documentation. A story UseCase names the caller's goal and defines the result/case vocabulary; scenario Given and When remain ordinary, readable test code and show the actual Tinytools setup and operation. Then/case assertions consume captured results. Use the repository's xUnit and FluentAssertions conventions unless a specific limitation is recorded with a compatible alternative. Split oversized scenarios by behavior without changing existing SPEC/US/SC identities unnecessarily.

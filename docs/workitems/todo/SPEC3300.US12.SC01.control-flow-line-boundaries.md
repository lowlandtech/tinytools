## Outcome

Control-flow rendering preserves source line boundaries after closing blocks and produces deterministic LF output on every supported operating system.

## Acceptance criteria

- [ ] UAC01: Rendering `before\n@if (Context.A == 1) {\nmid\n}\nafter` with `A == 1` returns exactly `before\nmid\nafter`.
- [ ] UAC02: Two adjacent true `@if` blocks with `one` and `two` bodies render exactly `one\ntwo` with one separator newline.
- [ ] UAC03: A blank source line after a closing block is preserved; the premium example renders `Premium.\n\nItems:` at the corresponding boundary.
- [ ] UAC04: Equivalent LF and CRLF input render identical canonical LF output on Windows and Linux.
- [ ] UAC05: Nested `@if` and `@foreach` output uses the same line-boundary contract without adding or removing body lines.
- [ ] UAC06: Focused and full test acceptance passes on `net8.0`, `net9.0` and `net10.0` with named, discovered case results.

## Refinement evidence

The reported reproducible failure is `Render("before\n@if (Context.A == 1) {\nmid\n}\nafter")` returning `before\r\nmidafter` on Windows; adjacent `@if` blocks return `onetwo`, while `@foreach` retains a separator. `TinyTemplateEngine.ProcessControlFlow` normalizes input line endings but plain lines use `AppendLine` and block results use `Append`, causing both the lost boundary and platform-dependent newlines. M1-003 is a dependency so this scenario uses the user's required visible Given/When test format. No implementation or test execution is claimed.

## Outcome

A caller cannot exhaust the host through the template surface: request rates are bounded per credential, the store and render dependency fail independently behind breakers, and an oversized render is refused before it runs.

## Problem

Render is the expensive operation and the store is the shared dependency, so both are abuse targets. Nothing currently bounds either, which makes the surface trivially exhaustible.

## Acceptance criteria

- [ ] UAC01: A fixed-window limit of 60 requests per credential per 60 seconds admits requests 1-60, refuses request 61 with 429 and an integer `Retry-After` of at least 1, and does not invoke its handler for the refused request.
- [ ] UAC02: Three consecutive store failures open the store breaker for 5 seconds; one half-open probe is admitted after the interval; success closes it. Store failures do not open or delay the independent render path.
- [ ] UAC03: Render accepts a UTF-8 template up to 256 KiB and JSON model up to 1 MiB, refuses either one byte over with 413 before calling the executor, and stops a render at the M7-008 10-second execution deadline with 504 and no partial output.
- [ ] UAC04: The observable order is authorization, rate limit, store breaker, handler; unauthorized calls consume no quota, rate-refused calls invoke neither breaker nor handler, and every refusal leaves the template store unchanged.
## Scenario contract

Given a fake clock, a counting template store, a counting executor and a production host with the `SC11` policy, When the requests hit the stated boundaries, failures and recovery interval, Then the use case records `RateLimitBoundary`, `StoreBreakerLifecycle`, `RenderBounds`, and `AdmissionOrder` with statuses, retry value, invocation counts and before/after store snapshots. Keep setup and HTTP calls visible in `SC04_EnforcesEndpointProtection.cs`; one Fact per UAC01-UAC04.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

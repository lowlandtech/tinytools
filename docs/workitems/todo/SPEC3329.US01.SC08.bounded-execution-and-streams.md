## Outcome

Render requests have stated size and execution-time budgets, while the existing template list is explicitly unpaged and deterministically ordered; request cancellation reaches store operations and cancellable rendering so the host does not continue abandoned work.

## Problem

Render and list have no declared bounds, and cancellation is passed to some calls but not proven to stop work before a side effect.

## Acceptance criteria

- [ ] UAC01: Render accepts `Template` up to 256 KiB UTF-8 and `Json` up to 1 MiB, and completes within 10 seconds; each exact boundary succeeds and one byte over returns 413 before executor invocation.
- [ ] UAC02: `GET /api/templates` remains an unfiltered, unpaged collection (no cursor/page query is added in this scope) and orders every response by ordinal template name then GUID; all mapped reads pass request cancellation to the store.
- [ ] UAC03: Cancelling an in-flight render before completion returns the named `Cancelled` result, leaves no stored template/version or partial response, and propagates cancellation to the executor.
## Scenario contract

Given the real HTTP host, a counting executor, seeded templates and caller-controlled cancellation, When payloads are sent at and beyond the byte limits, the collection is read, and render is cancelled, Then the results are `RenderBoundary`, `DeterministicUnpagedList`, and `CancelledWithoutEffects` with byte counts, ordered IDs, cancellation token observation and store snapshots. Keep Given/When code visible in `SC08_BoundsAndCancelsTemplateWork.cs`; one Fact per UAC01-UAC03.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

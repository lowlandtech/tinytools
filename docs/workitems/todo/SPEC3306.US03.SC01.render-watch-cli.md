## Outcome

Users can render one or many templates from files and refresh outputs when inputs change.

## Acceptance criteria

- [ ] UAC01: Given a template file, JSON model file and output path, when `render` runs, `RenderedFile` contains deterministic public-engine output and the process result identifies success.
- [ ] UAC02: Given a malformed template or invalid JSON, `RenderFailureResult` identifies the input and exits with the declared nonzero code without replacing an existing output with partial content.
- [ ] UAC03: Given a watched template/model dependency and a canceled watch process, `WatchRevisions` contains one render per relevant completed input change and shutdown completes without leaving a child process or file handle.
- [ ] UAC04: Given an unrelated file change, `UnrelatedChangeCount` does not trigger a render; the set of relevant files must be explicitly enumerated by the CLI contract.
- [ ] UAC05: Given a batch with valid and invalid entries, `BatchResults` contains one named result per input in stable input order and the exit policy matches the declared continue/fail-fast choice.
- [ ] UAC06: Given an output path outside the permitted workspace root, `RejectedOutputResult` is a named refusal and no file outside the root is created or modified.

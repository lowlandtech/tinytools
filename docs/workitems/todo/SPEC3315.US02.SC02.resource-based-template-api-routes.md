## Outcome

The template API exposes stable resource paths that do not reveal which plugin or package contributes the endpoints.

## Acceptance criteria

- [ ] UAC01: List, get, create, update, delete, render and version-validation operations are served under `/api/templates` and its resource subpaths; no public route includes the `tinytools` plugin identity.
- [ ] UAC02: OpenAPI and the mounted API endpoint inventory expose the resource routes and contain no `/api/tinytools/templates` route; the obsolete plugin-prefixed path does not reach a template operation.
- [ ] UAC03: Create responses publish a `Location` under `/api/templates/{id}` and do not emit plugin-prefixed links.
- [ ] UAC04: `HttpTemplateLibrary` uses the resource-based route for every operation, including render and validation, and its tests assert the observed request method, path and response.
- [ ] UAC05: The real-host endpoint specifications cover success and failure responses for the affected operations against the resource-based paths; no assertion accepts the obsolete path.
- [ ] UAC06: Added or changed behavior scenarios follow Agentic Gherkin with visible Given/When code, named case results, unique UAC traits and observed outcomes; the required layout diagnostic has zero findings for each changed scenario file.

## Scenario contract

Given a real Tinytools API host with an isolated SQLite database and seeded template, When a caller requests a template operation at `/api/templates` or a resource subpath, Then the response and any returned resource link use that path and the obsolete plugin-prefixed path does not dispatch the operation.

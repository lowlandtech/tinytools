## Outcome

The deployed host can be operated: requests are traceable, metrics are bounded and redacted, objectives are stated, and every operation maps to executed evidence from the deployed artifact.

## Problem

Local integration tests prove behaviour but not operability; there is no tracing, metric or header evidence from a deployed instance.

## Acceptance criteria

- [ ] UAC01: Requests and store calls are traceable end to end, metrics are bounded-cardinality and audit events are redacted.
- [ ] UAC02: Per-operation latency and error objectives are stated and a dependency failure and restart are survived.
- [ ] UAC03: Security and transport headers, CORS and the API-versus-SPA fallback behave as declared against an isolated host.
- [ ] UAC04: Every operation maps to executed SC01-SC10 evidence from the deployed artifact, with the exact versions and URLs recorded.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

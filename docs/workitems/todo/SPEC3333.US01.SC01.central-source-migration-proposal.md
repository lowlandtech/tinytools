## Why this document exists

Coordinator-1 asked for a separate proposal-state workitem for the Tinytools cut of the central-source
consolidation, rather than leaving the estimate inside an assessment. This is that workitem.

## The decision this waits on

Three consolidations are on the table for the shared contract surface. Tinytools consumes almost none of
it, so its cut is small in all three - but the cut differs, and the packages have to be republished and
redeployed whichever is chosen.

| Option | What changes here | Estimate |
|---|---|---|
| **A. Plugins becomes the sole central source** | nothing: no `LowlandTech.Core` package is referenced by this lane | **1** |
| **B. Core becomes the sole central source** | `PluginSurface` moves to a Core namespace - one `@attribute` line in `TemplatesPage.razor`; the package reference in `src/api` and `src/frontend`; three `using LowlandTech.Plugins;` in the packaging specs | **2** |
| **C. Core (backend) + Core.Frontend (browser), Plugins keeps API/App/product frontends** | B, plus splitting the reference by target - `src/api` takes `Core`, `src/frontend` and `src/app` take `Core.Frontend`. The browser-side identifier that decides it is `PluginSurface` | **3** |
| **D. Full repository move** | not a pin change: 12 projects, 63 workitems, CI, release, four package identities, the deployment descriptor and `#98` | **21**, not recommended |

Measured facts behind those numbers are in `SPEC3331-US01-SC01`.

## Proposed path and decision criteria

1. **Choose A, B or C** at the coordinator/milestone level. A is a no-op here and should not be recorded
   as a migration.
2. **Publish one proposal workitem per affected lane** first, as this lane was asked to; the shared
   decision is only real when every consumer's cut exists.
3. **Decide in one step, migrate in one step.** A half-migrated lane holds two `PluginSurface`
   namespaces and two pins, which is exactly the state that produced the Coder/Harness domain skew this
   workspace spent a day on.
4. **Migration cut:** edit the references and the attribute, run the full suite, repack the four packages
   at the declared version, refresh the workspace feed, redeploy, and record the deployment manifest
   (`ENGINE`-equivalent evidence: package hashes, deployment identity, observed plugin keys).
5. **Do not split the work across passes.** The cut is one session; a partial cut leaves the lane unable
   to pack.

## Risks

- **Two pins at once.** A stale `Plugins.Domain` pin alongside a new `Core` pin fails the deployment
  closure the same way the Coder package did; the migration must remove the old pin in the same commit.
- **`PluginSurface` namespace drift.** If Core and Plugins both expose the attribute during the
  transition, the assembly carries two and the binder picks one; the item must delete the old reference
  rather than add the new one beside it.
- **Deployment republish.** The Harness pins exact versions, so the cut is only complete when the
  deployment records the new package versions and the three plugins still compose.
- **Validator gap.** A `proposal` status cannot be expressed in the board today; if that is fixed, this
  item and `SPEC3332-US01-SC01` should be converted to it in one edit.

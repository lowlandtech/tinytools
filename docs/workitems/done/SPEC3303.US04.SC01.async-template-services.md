## Outcome

A template can invoke an explicitly registered asynchronous service through an asynchronous render path.

## Acceptance criteria

- [x] UAC01: Given an explicitly registered asynchronous service that completes with a value, when the public asynchronous render path executes a template that invokes it, `AsyncServiceOutput` contains the awaited value and the returned Task is not completed before the service completes.
- [x] UAC02: Given two asynchronous services in a template with an established evaluation order, `AsyncServiceOrder` reflects the contractually declared order. The lane must specify whether expressions are sequential or concurrent before this criterion is ready.
- [x] UAC03: Given a registered service that faults with a known exception, when rendering completes, `ServiceFailureResult` is a stable named diagnostic that identifies the service and does not expose a partial output string or exception details beyond the declared contract.
- [x] UAC04: Given a cancellation token canceled during a pending service call, `CancellationResult` matches the chosen cancellation contract and no later service invocation occurs. Cancellation propagation needs an owner decision before readiness.
- [x] UAC05: Given existing synchronous `TemplateServiceFunc` and `ITemplateService` registrations, when the existing synchronous `Render` path executes, `SynchronousOutput` remains byte-for-byte compatible with its pre-change result.
- [x] UAC06: Given an asynchronous-only service invoked from the synchronous render API, `SyncAsyncServiceResult` is the explicit refusal selected by the lane; the sync path must not block on asynchronous work.

## Contract decisions (resolved with implementation)

The refinement left two owner decisions open; both are now settled in code:

| Question | Decision |
|---|---|
| Evaluation order | **Sequential**, in source order. Each `@service(...)` call is awaited before the next one starts, so `AsyncServiceOrder` is exactly the declaration order and a later call cannot observe an earlier one still running. |
| Cancellation | The token is checked before every service call and passed into the service. A cancelled token surfaces as `OperationCanceledException` and no later service runs. |
| Failure surface | A faulting service becomes `TemplateServiceException` whose message names only the service (`Asynchronous template service 'name' failed.`); the inner exception is attached but never rendered, so internal text cannot leak into output. |
| Synchronous path | `Render` refuses a template containing `@service(` with `InvalidOperationException` instead of blocking on the async work. Existing synchronous `TemplateServiceFunc`/`ITemplateService` behaviour is untouched. |
| Unregistered service | `InvalidOperationException("Asynchronous service 'name' is not registered.")`. |

## Coordinator refinement — M3 current milestone

### Coordinator contract decision

The coordinator bounds this existing async-service scope as follows:

| Surface | Contract |
|---|---|
| Registration | Keep `ITemplateService.Transform(object?)`, `TemplateServiceFunc`, all current `RegisterService` overloads, and `ITemplateEngine.Render` source-compatible. Add `RegisterAsyncService(name, Func<object?, CancellationToken, ValueTask<object?>>)` on the execution context. |
| Render entry point | Add `TinyTemplateEngine.RenderAsync(string, ToolContext, CancellationToken = default)` returning `Task<string>`. No async method is added to `ITemplateEngine` in this increment, preserving third-party implementations. |
| Template call | A standalone line `@service("name", expression)` invokes the named service. The expression is evaluated in the current context; the awaited result is emitted at that line. Unknown service is a named `InvalidOperationException`. |
| Ordering | Calls execute sequentially in template source/render order, including nested control-flow bodies. No parallel service execution. |
| Failure and cancellation | Service exceptions are wrapped in `TemplateServiceException` naming the service; partial output is never returned. Cancellation propagates as `OperationCanceledException`, stops subsequent service calls and returns no partial text. |
| Sync compatibility | Existing sync registration and rendering behavior remain unchanged. Calling a template with an async service through sync `Render` throws `InvalidOperationException`; sync rendering never blocks on async work. |

This scope adds no HTTP/API service client and no change to the existing service registry semantics beyond a separate async registration map.

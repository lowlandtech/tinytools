## Outcome

Reusable template packs can be distributed and discovered without enlarging the core engine runtime.

## Acceptance criteria

- [x] UAC01: Given a valid package manifest, `PackIdentity` is stable and unique, and `EngineCompatibility` is a parseable range that admits the tested Tinytools engine version and rejects a version outside the range.
- [x] UAC02: Given the selected distribution mechanism and an installed pack, `EnumeratedTemplates` lists only manifest-declared template data with stable names and package provenance.
- [x] UAC03: Given a pack containing path traversal, executable content or undeclared files, `PackAdmissionResult` refuses the pack with a named reason before any content is rendered.
- [x] UAC04: Given an admitted template containing text that resembles code or markup, `RenderedPackText` treats it as template data under existing Tinytools semantics and does not load or execute code from the package.
- [x] UAC05: Given two packages declaring the same stable identity or template name, `CollisionResult` follows an explicit deterministic refusal/precedence policy and identifies both package identities.

## Contract decisions (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Distribution and discovery | A pack is a **NuGet package** carrying `tinytools/pack.json` plus its template files. Discovery uses whatever feed the host already restores from, so Tinytools adds no registry service and no engine runtime dependency. |
| Manifest | `id`, `version`, `engine` (range) and `templates: [{name, path}]`; `Identity` is `id@version`. |
| Engine compatibility | NuGet interval notation (`[2026.1,2027.0)`, `(,2.0]`) or a bare minimum (`>=2026.1.0`), compared on dotted numeric parts. A version outside the range is refused as `engine-incompatible`. |
| Trust model | A pack is **data only**. Admission never loads or executes anything from the package, and rendering runs the existing engine over template text, so code-like content is inert text. |
| Admission rules | Refused by name, before rendering: `path-traversal`, `undeclared-template`, `executable-content`, `unsupported-extension`, `undeclared-file`, `duplicate-identity`, `duplicate-template`, `invalid-manifest`, `engine-incompatible`. |
| Collision policy | Deterministic refusal, not precedence: a second pack with the same id or the same template name is refused and the reason names both identities. |
| Ownership | Packs are third-party artifacts; this repository ships the reader, the admission rules and the contract, not a pack content registry. |

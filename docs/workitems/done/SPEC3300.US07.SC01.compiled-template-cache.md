## Outcome

Callers compile a template once and render the immutable compiled plan against fresh execution contexts without sharing context state or rendered output.

## Refined API and cache contract

- Preserve the existing ITemplateEngine API and behavior.
- Add ITemplateCompiler.Compile(string source) and an immutable CompiledTemplate value that exposes its original source and Render(ToolContext context); TinyTemplateEngine implements both interfaces.
- Compile the existing variable, pipe-helper, comment and control-flow syntax into a reusable plan. Compilation must not resolve variables, invoke context services or capture a context.
- Cache plans per TinyTemplateEngine instance, keyed by the exact source string using ordinal comparison. The cache is thread-safe, uses least-recently-used eviction, and has a fixed capacity of 128 entries. A plan may be evicted and recompiled; callers must not rely on object identity after eviction.
- Rendering always reads the supplied current context. Never cache rendered output, model objects, services or context-dependent values. Different engine instances do not share entries.

## Acceptance criteria

- [x] UAC01: One compiled source rendered with two separate contexts produces each context's current values; neither result contains the other's values.
- [x] UAC02: Compiling the same exact source twice before eviction returns the same cached plan and repeated renders are equivalent to the existing ITemplateEngine.Render result.
- [x] UAC03: A one-character source change creates a distinct plan; neither source renders stale text or output from the other.
- [x] UAC04: Concurrent compile/render calls for one source return one cached plan before eviction and preserve each caller's separate context/output.
- [x] UAC05: After filling the 128-entry cache and touching a selected entry, the least-recently-used untouched entry is evicted and recompiles; the recently used entry remains cached. Eviction changes compilation reuse only, never render output.

## Scenario contract

Use case: a template author reuses a compiled template across changing execution contexts. Each test scenario keeps new TinyTemplateEngine, context construction, Compile/Render and the comparison call visible in the scenario source; the story UseCase/result model names the caller goal and observed case but does not hide Given or When.

| Named result case | Given / When kept visible in scenario source | Observable result |
|---|---|---|
| ContextIsolation | One engine, one compiled source, then two separately constructed contexts / compile and render once with each context | Each output contains only its own context value; UAC01. |
| ReusesCachedPlan | One engine and one unchanged source / compile twice before eviction and render both | Both compile calls return the same plan and both outputs equal the existing renderer; UAC02. |
| SourceChange | Two sources differing by one character / compile and render each | Plans and rendered text remain distinct; UAC03. |

| LeastRecentlyUsedEviction | 128 distinct sources, then touch one selected entry / compile a 129th source and request the cold and touched entries | Only the least-recently-used entry is recompiled; the touched entry remains cached and output remains correct; UAC05. |

## Evidence
Implemented at `2bfef49` on `develop`, additively: `ITemplateEngine` and every existing consumer are untouched.

- `ITemplateCompiler.Compile(string)` and the immutable `CompiledTemplate` (`Source`, `NormalizedSource`, `Engine`, `Render(ToolContext)`) are new types in `src/lib/Core`; `TinyTemplateEngine` implements both interfaces.
- Compilation normalizes line endings and binds a render delegate - it never resolves variables, calls a helper, touches a service or captures a context. The plan holds no context, model or rendered output, so output cannot be cached.
- `TemplatePlanCache` is an internal, fixed-capacity (128) least-recently-used cache: ordinal key comparison, a `Dictionary` plus `LinkedList` under one lock, `TryGet` promotes the hit to most recently used, and insertion evicts the least recently used entry beyond capacity. Plans are per engine instance, so two engines never share entries.

Two scenarios cover the five criteria with ten cases through the `CompiledTemplatesUseCase`:

| Case | Criterion | Observed |
|---|---|---|
| `SC01` UAC01/UAC02 | context isolation | one plan, two contexts: `Hello Ada` and `Hello Grace`, neither leaking into the other |

One implementation correction worth recording: the first version of the eviction case read the "cold" plan *before* overflowing the cache, which promoted it to most recently used and made the eviction assertion fail. The case now captures the reference during the fill loop, so the entry is genuinely cold when the cache overflows.

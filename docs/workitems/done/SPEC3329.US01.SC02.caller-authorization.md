## Outcome

The template surface is reachable only by a caller holding the configured credential, refusals are uniform and silent, and a deployment with no credential configured refuses everything instead of falling open.

## Problem

The API-key policy exists and is applied to the route group, but nothing asserts the negative paths: an absent key, a wrong key, a missing configuration value. Those are the paths an attacker uses, and an untested refusal is a refusal nobody knows works.

## Acceptance criteria

- [x] UAC01: A caller holding the configured key is accepted.
- [x] UAC02: A caller with no key is refused with 401.
- [x] UAC03: A caller with a wrong key is refused with 401.
- [x] UAC04: A wrong-cased key is refused, so the comparison is exact.
- [x] UAC05: The absent-key and wrong-key refusals are byte-identical.
- [x] UAC06: A refusal never contains the expected key value.
- [x] UAC07: A host with no configured key refuses every call instead of falling open.
- [x] UAC08: Development-mode anonymous access is asserted explicitly, so the bypass is visible.
- [x] UAC09: All seven operations refuse anonymous callers the same way.

## Scenario contract

Given a host configured with a key, when requests arrive with a valid key, no key and a wrong key, then only the valid one reaches the handler and the other two receive the same refusal.

The scenarios live under `src/test/SPEC3329.EndpointProtection/US01.EndpointProtection/` and follow the
shared Agentic Gherkin grammar: one scenario class per file, Given construction and When calls visible in
the scenario source, one `[Trait("UAC", "NN"), Fact]` per single-line assertion, and a unique UAC per file.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

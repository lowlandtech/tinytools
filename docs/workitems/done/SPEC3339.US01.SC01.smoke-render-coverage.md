## Outcome

The consumer gate covers the product's core promise as well as the watcher: a published package renders a
template with a model, and its strict mode refuses an unknown context key by name.

## Why

`SPEC3337-US01-SC01` built the gate for the one behaviour that had regressed - the watcher - and that was
right at the time: a gate should be written for what actually broke. But the watcher is not what most
consumers use the package for. Rendering is. Leaving it unverified meant the gate would pass a package whose
renderer was broken, which is a worse failure than the one it was built to catch.

## Change

Two assertions added to `eng/smoke-package.consumer.cs.txt`, so the published package is exercised through
its public surface exactly as a consumer would call it:

| Case | Expected |
|---|---|
| `Render("Hello ${Context.Model.Name}!", context)` with `Model = new { Name = "Ada" }` | `Hello Ada!` |
| the same engine in `TemplateRenderOptions.Strict` with `${Context.Absent}` | throws, and the message names `Absent` |

## A wrong assertion, caught before it shipped

The first version of the strict case used `${Context.Model.Missing}` and asserted that the error named
`Missing`. It failed, and the product was right: strict validation checks the **root** key through
`context.Has(root)`, so a nested path under an existing model is not an unknown variable. The assertion was
wrong, not the engine - `${Context.Absent}` is the honest case. Recorded here because the mistake was mine
and the next reader should not repeat it.

## Scope boundary

It verifies render and strict diagnostics through the public API; it does not attempt the CLI, the api
plugin or the editor. It still does not run in CI, for the reason recorded in `SPEC3337-US01-SC01`: CI has
no workspace feed.

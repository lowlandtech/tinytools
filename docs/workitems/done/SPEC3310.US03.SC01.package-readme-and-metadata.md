### The readme decision (UAC01)

Two candidates existed and the project file was not obviously pointing at either:

- `readme.md` at the repository root (17 KB) - the project showcase: badges, feature matrix, long examples.
- `src/README.md` (2.7 KB) - the install-first document for package consumers.

`src/README.md` is the package readme: it opens with `# LowlandTech.TinyTools` and a `dotnet add package LowlandTech.TinyTools` install block, which is what a NuGet consumer needs. The root `readme.md` stays the repository front page and is deliberately **not** packed. That choice is now written into the project file as a comment, so the next reader does not have to reconstruct it.

The include is pinned with `Link="README.md"` and `PackageReadmeFile` stays `README.md`, so the packaged name no longer depends on which file path happened to resolve.

### Property duplication (UAC02)

`PublishRepositoryUrl`, `EmbedUntrackedSources` and `DebugType`/`IncludeSourceRevisionInInformationalVersion` were declared twice, and `ContinuousIntegrationBuild` was declared twice as well - once under `Condition="'$(GITHUB_ACTIONS)' == 'true'"` and once unconditionally `true` later in the same `PropertyGroup`, which overrode the condition on every build. The duplicate block is removed; `ContinuousIntegrationBuild` is now set only under its CI condition, with a comment explaining why.

### Case-sensitivity check (UAC04) - open, with the blocker named

The on-disk casing is verified: `src` contains exactly one file named `README.md` and **no** `readme.md` (checked with case-sensitive comparison), and the include plus `PackageReadmeFile` use that exact casing, so a case-sensitive filesystem resolves the same file and no differently-cased sibling exists to be selected silently.

A real pack on a case-sensitive filesystem could **not** be executed in this environment:

- WSL has no `/mnt/d` mount in the available distribution, so the repository is not visible to it;
- `fsutil file setCaseSensitiveInfo` on a scratch directory returns `Access is denied` (needs elevation), so a case-sensitive directory cannot be created locally;
- no local .NET SDK container image exists (`docker images` has only `lowlandtech-backend:*`), and pulling one plus this repository's feed is not part of this scope.

Closing UAC04 needs one of: a Linux/container `dotnet pack` of this project, or a case-sensitive volume holding the checkout. Until then the static casing proof and the content hash above stand, and the item stays `doing` rather than claiming a pack that was not run.

### Case-sensitive pack (UAC04) — executed, plus a negative control

The blocker recorded above was resolved by packing inside a Linux container, so the
sources live on an ext4 filesystem that is genuinely case-sensitive:

- `docker pull mcr.microsoft.com/dotnet/sdk:10.0`, then `docker create` a one-shot
  container and `docker cp` `src/lib`, `src/README.md`, `icon.png` and `changelog.md`
  into it, so nothing is bind-mounted from the case-insensitive NTFS host.
- `dotnet pack LowlandTech.TinyTools.csproj -c Release` inside that container succeeds
  and the extracted nuspec reports `readme` = `README.md`, `icon` = `icon.png`,
  `version` = `2026.5.31`, the same four package files, the same dependency list per
  target framework, and a packaged `README.md` whose SHA-256 is
  `5A2E03639752BAB53357DE8308568169FAEE7170BF619C5F2D4063168B0EA952` - identical to the
  Windows pack and to `src/README.md`, still different from the root `readme.md`.

Negative control: renaming the container's `src/README.md` to `readme.md` and repacking
with a clean `obj`/`bin` still produced a package whose `README.md` has the same hash.
That is worth recording as a finding rather than a nuisance: MSBuild matched the
explicitly-cased include even on a case-sensitive filesystem, so a casing mismatch
cannot silently select a *different* readme here - and the content hash is what proves
which file was packed in the first place. The container was removed afterwards and no
repository file outside this workitem changed.

All four criteria are now met, so the item is done.

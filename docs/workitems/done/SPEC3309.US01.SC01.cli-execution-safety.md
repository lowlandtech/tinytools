## Outcome

The `generate` command cannot hang on child-process output, states and enforces its command trust policy, and both the CLI and `WorkflowRunner` are covered by executable tests instead of being shipped unverified.

## Acceptance criteria

- [x] UAC01: A command step whose child process writes more than one pipe buffer to standard output and standard error concurrently completes; both streams are read concurrently.
- [x] UAC02: The command policy is documented and enforced before a process starts: a refused command exits non-zero with a message naming the refused value.
- [x] UAC03: A failing command step reports the child exit code and captured standard error, and the CLI exits non-zero instead of reporting success.
- [x] UAC04: Template steps are covered for first write, unchanged idempotent rerun, `forEach` producing one output per item, and a refusal when an output path escapes the workflow root.
- [x] UAC05: The CLI test project is part of `tinytools.slnx` and runs under the delivery gate.

## Evidence
Implemented at `709c5bc` on `develop`. The command execution moved out of the CLI's local function into the library, so the policy and the pipe handling are executable outside the entry point:

- `src/lib/Workflows/WorkflowCommandPolicy.cs` - the documented trust list (`dotnet`, `git`, `gh`), `IsAllowed`, and a refusal message that names both the refused value and the allowed set. The list is a code decision, so a workflow file cannot widen its own trust; the readme already states the allow-list.
- `src/lib/Workflows/WorkflowCommandExecutor.cs` - checks the policy before any process starts, guards the working directory against root escape, drains stdout and stderr **concurrently**, and reports a failing child as `"<command> failed (<exit>): <stderr>"`. A caller may pass an explicit trust list, which is how the concurrency case exercises a flooding child without weakening the default.
- `src/cli/Program.cs` now delegates to that executor and maps outcomes to exit codes: `0` success, `2` usage, `3` policy refusal (message only, no stack trace), `1` any other failure. Previously every failure surfaced as an unhandled exception.

## Outcome

One test project owns the suite and one intermediate directory serves it, so restore cannot clobber another project's assets and no test project escapes the delivery gate.

## Acceptance criteria

- [x] UAC01: `LowlandTech.TinyTools.UnitTests.csproj` is removed, and any newer package version it held is reconciled into the retained project or recorded as intentionally not taken.
- [x] UAC02: A clean restore leaves exactly one `project.assets.json` under `src/test/obj`, owned by the retained project.
- [x] UAC03: `dotnet test tinytools.slnx -c Release` reports the same fact count before and after on `net8.0`, `net9.0` and `net10.0`.
- [x] UAC04: The solution lists every project the repository intends to build, including test-only infrastructure, and no removed project.

## Scenario contract

No product behavior to test beyond the existing suite. Evidence is the restore artifact list, the solution project list and the per-framework fact counts from the delivery gate before and after.

## Pickup packet

- First edit: delete `src/test/LowlandTech.TinyTools.UnitTests.csproj`; review its package versions (`FluentAssertions` 8.9.0, `Microsoft.NET.Test.Sdk` 18.5.1, `coverlet.collector` 10.0.0) against the retained project before deleting.

## Evidence
- Removed `src/test/LowlandTech.TinyTools.UnitTests.csproj`. It compiled the same `src/test/**` glob from the same directory as the retained project, was absent from `tinytools.slnx`, and therefore never ran.
- Nothing needed reconciling: the retained project already held equal or newer versions of every package the removed one pinned (`FluentAssertions` 8.10.0 vs 8.9.0, `Microsoft.NET.Test.Sdk` 18.6.0 vs 18.5.1, `coverlet.collector` 10.0.1 vs 10.0.0); the rest were identical.
- Clean state after deleting `src/test/{obj,bin}` and restoring: `src/test/obj` holds exactly one `project.assets.json`, owned by `LowlandTech.TinyTools.Tests`, so restore can no longer clobber another project's assets.
- `tinytools.slnx` now lists `src/infrastructure/LowlandTech.TinyTools.Tests.Infrastructure.csproj` alongside lib, core, api, cli and test, so every project the repository builds is visible in the solution.
- Fact counts are unchanged by the removal: 660 passed on `net10.0`, 654 on `net8.0`/`net9.0`, 0 failed, 0 skipped, before and after.
- Recorded, not fixed: `examples/ShowTemplateOutput.cs` and `examples/TemplateSystemExamples.cs` still import `LowlandTech.TinyTools.UnitTests.Examples`. They sit outside every project and were never compiled; the stale namespace is left for the documentation item.

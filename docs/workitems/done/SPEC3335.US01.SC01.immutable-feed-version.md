# SPEC3335-US01-SC01 — Refuse to republish a package version in the feed

- **Milestone:** M5
- **Status:** done
- **Priority:** P1
- **Owner:** tinytools
- **Runner:** tinytools
- **Coordinator:** coordinator-1
- **Depends on:** None
- **Scope delivered:** SPEC3335-US01-SC01
- **Refined:** true
- **GitHub issue:** https://github.com/lowlandtech/tinytools/issues/115

## Outcome

A version in the workspace feed identifies one artifact. Packing a version that is already published
stops before writing anything, so a consumer's version-plus-digest pin can never silently start
describing different bytes.

## Why: a measured incident

On 2026-11-08 this lane repacked `LowlandTech.TinyTools.Frontend 2026.10.4` in place three times while
building the Harness deployment. On 2026-11-20 the Backend lane reported the consequence:

> Backend's published-projection acceptance pins `LowlandTech.TinyTools.Frontend` 2026.10.4 at SHA-256
> `5A6130AB…DDE0779`, but `D:/lowlandtech/packages/…2026.10.4.nupkg` (dated 2026-11-08 02:45) is
> `A90320F8…F680E497`, so three facts fail with `InvalidDataException` before any product code runs.

The pinned digest was the original content; the feed now held a different build under the same version,
and the original was gone. That is the failure this scope removes: not a bad package, an unusable
identity.

## What was measured before choosing the guard

A byte-equality guard was the obvious design and it does not work on this toolchain:

```
pwsh eng/pack-feed.ps1 -Feed <empty dir>      # writes 4 archives
pwsh eng/pack-feed.ps1 -Feed <same dir>       # repacks the same tree
-> ABF160647A04C8EF vs 55EEE7E1DD21CD8B for the same project, same commit, same version
```

`dotnet pack` is not byte-deterministic here, so "same bytes means safe" would both miss real content
changes and refuse harmless ones. The guard therefore enforces the simpler, stronger rule: **a published
version is immutable.**

## Change

`eng/pack-feed.ps1`:

1. reads the version from `Directory.Build.props`, the single version authority;
2. packs the four shipped projects into a staging directory, so the feed is untouched until every
   archive exists;
3. refuses to move any archive whose name is already in the feed, naming the published digest and the
   digest just built, and exits non-zero with the recovery: bump the version with
   `eng/set-version.ps1`, then pack.

## Verification

```
# a version not yet in the feed is written
pwsh eng/pack-feed.ps1 -Feed $env:TEMP\tt-feed2
-> Wrote LowlandTech.TinyTools.2026.10.6.nupkg BC7A680691109FA9
   Wrote LowlandTech.TinyTools.Api.2026.10.6.nupkg 13A15E03B7C83A11
   Wrote LowlandTech.TinyTools.Core.2026.10.6.nupkg 781E51622A73F0CE
   Wrote LowlandTech.TinyTools.Frontend.2026.10.6.nupkg C335B9CFD160B232
   Feed … now carries version 2026.10.6.

# the same version again is refused, and nothing is overwritten
pwsh eng/pack-feed.ps1 -Feed $env:TEMP\tt-feed2
-> REFUSED LowlandTech.TinyTools.2026.10.6.nupkg: published BC7A680691109FA9, this build produced 8FBB3C633B190C7A
   REFUSED LowlandTech.TinyTools.Api.2026.10.6.nupkg: published 13A15E03B7C83A11, this build produced 0FB4A1DA8EA8B937
   REFUSED LowlandTech.TinyTools.Core.2026.10.6.nupkg: published 781E51622A73F0CE, this build produced 64DB17F0DC65AE98
   REFUSED LowlandTech.TinyTools.Frontend.2026.10.6.nupkg: published C335B9CFD160B232, this build produced E872D20026EEA46D
   exit code 1, "… a version is immutable. Bump it with eng/set-version.ps1 … Nothing was overwritten."
```

The published digests above are unchanged after the refused run, which is the property the scope is
about.

## What this does not fix

The historical damage stays: `2026.10.4` and `2026.10.5` in the feed are already ambiguous, and the
Backend lane has been told to pin `2026.10.6` (Frontend
`48B1021628B9497A52463F034B0B440139F8AC0315E8E0EFB3AF2A8173CD701F`, Api
`CE291AACC5E63ACF14A8ED210A7EA08AB6434DD12A8A3F24DCEA7D4C1C0BB58F`). Removing published archives is a
feed-owner decision, not this lane's.

## Acceptance criteria

- [x] UAC01: The script packs the four shipped projects at the version `Directory.Build.props` declares.
- [x] UAC02: An archive that already exists for that version is never replaced, and the run fails naming the published and built digests.
- [x] UAC03: A version not yet in the feed is written, verified against an empty feed.
- [x] UAC04: The non-determinism that rules out a byte-equality guard is measured and recorded.
- [x] UAC05: The recovery is stated in the failure message and the feed is left untouched on refusal.

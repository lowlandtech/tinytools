## Outcome

A `src/app` Blazor host serves the Templates page built from LowlandTech.Components primitives and the imported store, with no bespoke UI kit.

## Acceptance criteria

- [x] UAC01: `src/app` targets `net10.0`, references `LowlandTech.Components`, and hosts Blazor Server rendering with the Templates page at `/templates`.
- [x] UAC02: The page composes existing components for layout, command bar, data list and forms; bespoke markup is limited to the page's own layout and is documented in the deviation ledger.
- [x] UAC03: The page reads and dispatches the imported store only; it makes no direct HTTP call and constructs no `HttpClient`.
- [x] UAC04: The API base address comes from configuration and a missing value fails fast with a named message that says what to set.
- [x] UAC05: A bUnit fact renders the page with a stubbed store and asserts the loaded templates are visible and the command bar actions are present.
- [x] UAC06: `dotnet run --project src/app` serves `/templates` against a running `src/api`, and the exact commands and URLs are recorded in evidence.
- [x] UAC07: The app carries the Harness Tailwind setup in its own `wwwroot`: `package.json` with `build:css`/`watch:css` over `@tailwindcss/cli`, `css/input.css` importing `tailwindcss` and naming the Razor sources with `@source`, and a committed `wwwroot/app.css`. `dotnet build` runs the CSS build only when `SkipTailwindBuild` is not `true`, and the Tailwind sources are removed from the published content.
- [x] UAC08: A build with `SkipTailwindBuild=true` succeeds without Node installed and serves the committed `app.css`, so an offline or Node-less machine can build the solution.

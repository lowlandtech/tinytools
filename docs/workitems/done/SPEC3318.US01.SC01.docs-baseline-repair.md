### Measured cause of the mirror drift (2026-10-30)

`--verify-only` reports drift for all 47 managed issues, and the cause is not only the bodies.
Measured with a locally patched copy of the shared tool (not committed) that keeps an existing marked
body:

- `--dry-run` -> `ok=true items=47`, every action `update`, so identity resolves and nothing needs
  creating.
- With `--preserve-body` the plan is still `update=47`, which proves the bodies are not the only
  difference.
- Comparing one item by hand: the tool wants the title `"<scope>: <title>"` (for example
  `SPEC3300-US03-SC02: Preserve comparison operator precedence`), while the issue is titled
  `Operator precedence bug in TinyTemplateEngine condition evaluation`. State and label sets also
  differ, because the issues predate the managed convention.

So a content-preserving reconciliation has to decide one thing first: does the mirror adopt the
managed title convention (renaming all managed issues once), or does the tooling accept an
identity-and-body-preserving mode for legacy issues? A `--preserve-body` flag alone does not clear the
drift, which is worth knowing before anyone runs `--apply` on 47 issues expecting it to work.

Recommendation to the tooling owner: add `--preserve-body` **and** `--preserve-title` (identity-only
mode), then `--verify-only` means "the marker resolves and the state matches source", which is the
claim this lane can actually stand behind. Until then the lane keeps `creates=0` as its evidence and
claims no mirror completeness.

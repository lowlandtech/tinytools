## Outcome

A team can pin the rendered output of each template and be told exactly what changed when the model or the template moves.

## Problem

Generators are adopted only when their output is reviewable. Today a caller has to build its own diff harness to notice that a template change altered a generated file.

## Contract decisions (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Storage | one `.approved/<template>.txt` per case beside the template, so a diff is a normal review artifact and no binary store is involved |
| Failure output | the first differing line plus a unified diff of at most 40 lines, never the whole file |
| Update path | an explicit `--approve` flag rewrites approved files; a normal run never mutates them |
| Scope | the CLI surface only; no test-framework integration, so it works from any CI runner that can execute dotnet |

## Acceptance criteria

- [x] UAC01: Running `tinytools test` over a case with a matching approved file reports success and writes nothing.
- [x] UAC02: A changed rendering fails with the first differing line number and a bounded diff.
- [x] UAC03: `--approve` rewrites only the approved files for the cases that ran, leaving others untouched.
- [x] UAC04: A case with no approved file fails and states the exact path it expected.
- [x] UAC05: A malformed template reports the engine's syntax diagnostic rather than a snapshot diff.

## Scenario contract

Scenario `src/test/SPEC3325.Snapshots/US01.Approvals/SC01_ApprovesRenderedOutput.cs` creates a temporary workspace, runs the approval flow, and asserts the reported outcome, the diff bound and the files touched by `--approve`.

## Evidence

Checkpoint after this change. `src/lib/Testing/TemplateSnapshotRunner.cs` and the `tinytools test`
command implement the approval flow with the layout the contract fixed: `name.tmpl`, an optional
`name.model.json` and `name.approved.txt`.

- `Discover` orders cases by name, so a run and its diff are deterministic.
- A case with no approval fails and names the path it expected; `--approve` writes it.
- A changed case reports the first differing one-based line plus a diff capped at 40 lines, and writes
  nothing unless `--approve` is passed.
- A malformed template reports the engine's syntax diagnostic rather than a diff, because a diff of a
  template that cannot render is noise.
- `tinytools test <dir> [--approve]` exits `0` when every case matches, `1` when any case fails, `2`
  when the directory holds no templates.

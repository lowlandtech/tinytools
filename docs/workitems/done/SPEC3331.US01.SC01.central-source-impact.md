## Outcome

A measured answer to one question: what does it cost Tinytools if Core or Plugins becomes the sole
central source, including the `Core` + `Core.Frontend` split the coordinator asked about - and what
would a full repository move cost instead.

## What Tinytools actually consumes

Measured from the tree, not estimated:

| Shared package | Referenced by | Code usage |
|---|---|---|
| `LowlandTech.Plugins.Domain` | `src/api`, `src/frontend` | **one attribute**: `[PluginSurface("TemplatesPage", …)]` on the page; the package also carries `lowlandtech/plugin.json` and `lowlandtech/deployment.json`, which are documents, not types |
| `LowlandTech.Components` | `src/app`, `src/frontend` | `@using LowlandTech.Components` in three Razor files, `<Button>`/`<DataGrid>` in the templates page, one `_content/LowlandTech.Components/css/components.css` link |
| `LowlandTech.Core` | **nothing** | none - `LowlandTech.TinyTools.Core` is this product's own project, not the shared contract |
| `LowlandTech.Plugins` (reader) | test project only | three `using LowlandTech.Plugins;` in the packaging specs |

Both pins currently match the Harness: `Plugins.Domain` 2026.10.1-20261029231326395491648 and
`Components` 2026.10.3-20261030235445133125670.

## Scenario comparison

### A. Plugins becomes the sole central source

**No impact.** Tinytools references no `LowlandTech.Core` package at all, so dissolving or absorbing
Core cannot change a Tinytools pin. The only shared contract it consumes is `Plugins.Domain`, which
survives by definition in this option.

### B. Core becomes the sole central source

Impact is one attribute and two references:

| Change | Files |
|---|---|
| `PluginSurface` moves to a Core namespace | `src/frontend/Features/Templates/TemplatesPage.razor` (one `@attribute` line) |
| the package reference | `src/api/*.csproj`, `src/frontend/*.csproj` |
| the reader used by the packaging specs | `src/test/SPEC3317.../UseCases/PluginPackagingUseCase.cs` and two scenario files |

Nothing else moves: the manifests are documents, the deployment descriptor is a document, and no
Tinytools type derives from a Plugins type.

### C. Core (backend) + Core.Frontend (browser), Plugins keeps API/App/product-frontend

Impact is B plus a target split Tinytools already has: `src/api` is backend and would take `Core`,
`src/frontend` and `src/app` are browser and would take `Core.Frontend`. The identifier the browser
needs - `PluginSurface` - is the one that would have to exist in the browser layer, which is exactly
where the split is decided.

### D. Full repository move

Not comparable in kind: 12 projects, 61 workitems, the CI matrix, the release workflow, four package
identities, the deployment descriptor and the VSIX item would all move, and the deployment pins would
change for every consumer. This is the option the numbers below are meant to price against.

## Estimates (1-40, planing poker)

| Option | Estimate | Basis |
|---|---|---|
| A: Plugins sole source | **1** | no change |
| B: Core sole source | **2** | one attribute, two csproj references, three test usings, repack, redeploy |
| C: Core + Core.Frontend split | **3** | B, plus splitting the reference by target and re-verifying both packages |
| D: full repository move | **21** | everything above plus CI, release, package identity, deployment and the VSIX |

## Assumptions and cadence

- No consumer-side API change to `PluginSurface` or the Components surface; the attribute keeps its
  shape and the page keeps its controls.
- Tinytools keeps its own product packages and its single version authority in
  `Directory.Build.props`.
- The deployment is republished after the pin change, because the Harness pins exact versions.
- Cadence: whichever option is chosen, the Tinytools cut is one workitem of one work session -
  edit, `dotnet pack` the four packages, refresh the workspace feed, run the deployment, record the
  manifest. The two-day figure a move would need does not appear here.

## Recommendation

Take **B or C**, not A and not D. A leaves Core's problem unsolved for this lane; D spends a
multi-week move on a surface whose shared usage is a single attribute and a UI library. If the
`Core.Frontend` split is chosen for other lanes, Tinytools pays three points rather than twenty-one.

## Outcome

Templates can reuse nested fragments with explicit context isolation.

## Acceptance criteria

- [x] UAC01: Given a registered fragment source and a parent template that names it, when the public `TinyTemplateEngine.Render` renders the parent, the captured `IncludedText` is exactly the fragment output at the include position.
- [x] UAC02: Given a parent and two fragments where one names the other, when the parent is rendered, `NestedText` contains each fragment once in declaration order and surrounding parent text remains in place.
- [x] UAC03: Given the same registered fragment names with different caller data, when two parent renders execute, `CallerOneText` and `CallerTwoText` reflect the data explicitly passed to each render; neither render observes values captured from the other call. The implementation contract must state whether fragment context is shared or projected before this criterion is ready.
- [x] UAC04: Given a missing fragment reference, when the public render executes, `MissingFragmentResult` names the unresolved fragment and no partial string is returned.
- [x] UAC05: Given direct and indirect recursive references, when validation or rendering executes, `CycleResult` is a stable named refusal and no unbounded recursion occurs. The owner must choose the diagnostic surface and cycle policy before this criterion is ready.
- [x] UAC06: Given an empty fragment and a fragment containing newlines, when the parent renders, `EmptyFragmentText` and `MultilineFragmentText` preserve the engine's existing LF normalization and block line-boundary contract.

## Refinement decisions (lane-owned, resolved 2026-10-30)

The refinement section above delegated the contract to the lane. These are the decisions,
taken before implementation and now binding:

| Question | Decision |
|---|---|
| Registration API | `TinyTemplateEngine.RegisterFragment(name, source)` and `UnregisterFragment(name)`; fragments belong to one engine instance, are compared ordinally, and are exposed read-only through `Fragments`. No filesystem, network, package or cross-engine resolution. |
| Include syntax | `@include("name")` or `@include('name')`, anywhere in template source. It is a source-level composition, not a control-flow statement. |
| Context visibility | A fragment renders with **the caller's own context** (shared projection, no copy): values passed to that `Render` are visible inside every fragment it pulls in, and nothing is captured between renders. Caller isolation therefore comes from the context each caller builds, which UAC03 exercises with two different contexts on one engine. |
| Cycle policy | The engine keeps an include stack per render. A direct or indirect repeat raises `InvalidOperationException("Include cycle detected: a -> b -> a")`, naming the path, before any output exists. |
| Missing fragment | `InvalidOperationException("Include 'name' was not registered on this engine.")` - named refusal, no partial output. |
| Partial output | Impossible by construction: includes are expanded to plain template source **before** the control-flow and variable passes run, so a failure happens before any text is produced. |
| Line boundaries | Fragment source is inserted verbatim, so the existing LF normalization and block line-boundary contract apply unchanged; the multiline case asserts the exact `Line one\nLine two` result. |

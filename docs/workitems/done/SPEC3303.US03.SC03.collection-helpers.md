## Contract decisions (resolved with implementation)

| Question | Decision |
|---|---|
| Predicate grammar | `where:path==value` and `where:path!=value`; the value is compared as text, case-insensitively, with bools rendered `true`/`false` and numbers with the invariant culture. A predicate without an operator raises `ArgumentException`. |
| Null and empty input | `where`, `groupby`, `orderby` and `distinct` treat a null or non-enumerable value as an empty sequence rather than throwing. |
| Ordering | `orderby:path` is **stable**: equal keys keep source order. A member missing from any item raises `ArgumentException("orderby: 'path' is not a member of every item.")`, matching the same refusal for `groupby`. |
| Grouping | `groupby:path` returns `IGrouping<object?, object?>` in **first-seen key order**, with source order preserved inside each group. |
| Distinct | Keeps the first value of each distinct one, comparing with `object.Equals`, so repeated references collapse and value types compare by value. |
| Method access | Members are read from a dictionary (case-insensitive key) or a public property, so template models and anonymous objects behave the same. |
| Chaining | Helpers compose left to right through the existing pipe syntax, including from `ResolveExpression`. |

## Coordinator refinement — M3 current milestone

### Coordinator contract decision

The coordinator fixes a bounded expression grammar for the four already-planned collection helpers. It uses no reflection method calls, arbitrary C#, or culture-dependent comparisons.

| Helper | Contract |
|---|---|
| `where:path<op>literal` | `path` is a dot-separated property path; operators are `==`, `!=`, `<`, `<=`, `>`, `>=`. Literals are quoted strings, invariant decimal numbers, `true`, `false`, or `null`. Path lookup supports string-keyed dictionaries (ordinal-ignore-case keys) and public readable instance properties. The result preserves source order. |
| `orderby:path[:asc|desc]` | Sorts by the same path rules; ascending is default. Ordering is stable. Strings use ordinal comparison, numbers use invariant numeric comparison, booleans use false-before-true; null sorts first ascending and last descending. Missing paths or incomparable values throw `ArgumentException` naming the helper/path. |
| `groupby:path` | Returns `IEnumerable<IGrouping<object?, object?>>`; groups appear in first-seen key order and each group's members retain source order. Keys use the same equality rules as `distinct`. |
| `distinct` | Uses `object.Equals`/`GetHashCode`, retains the first equal element and preserves source order. No custom comparer parameter is added. |
| Null/empty input | Null and empty enumerables produce empty sequences for all four helpers. Strings are scalar values and are not treated as collections. |
| Invalid expressions | Missing path, malformed operator/literal, unsupported value type or incompatible comparison throws `ArgumentException` with helper and input; unknown helper behavior is untouched. |

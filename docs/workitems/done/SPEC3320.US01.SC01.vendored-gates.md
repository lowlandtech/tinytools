## Outcome

CI enforces the behavior-test layout grammar and the roadmap contract from inside this repository,
instead of a step that warns and skips because the shared checker is not in the checkout.

## Problem

The `Verifiable gates` job runs:

    CHECKER="$GITHUB_WORKSPACE/eng/verify-test-layout.py"
    if [ ! -f "$CHECKER" ]; then
      echo "::warning::Shared layout checker not present in this checkout; ..."
      exit 0
    fi

`$GITHUB_WORKSPACE` is this repository, which has no `eng/` directory, so on CI the layout gate has
only ever **warned and passed**. The roadmap validator has the same gap. That means the two checks
this lane quotes in every closure are enforced only on the developer machine.

## Contract (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Where the tools live | vendored verbatim into `eng/` in this repository, with a provenance header naming the source path and commit |
| Why vendoring rather than referencing | CI has no access to the workspace checkout, and the shared tools are Python scripts with no dependencies; a pinned copy is the only way CI can run the same rules the lane quotes |
| Drift control | each file carries `Source: <workspace path>@<commit>`; a test asserts both files exist and exit non-zero on a known-bad input, so a silently empty or truncated copy fails |
| CI wiring | the job runs both from `eng/`, fails on any layout violation or roadmap diagnostic, and no longer warns-and-skips |
| Not claimed | the scripts are not modified; upstream fixes are re-vendored rather than patched here |

## Acceptance criteria

## Scenario contract

Scenario `src/test/SPEC3320.Gates/US01.Vendored/SC01_RunsTheGates.cs` invokes each vendored script
as a process against this repository and against a mutated copy, asserting exit codes and the parsed
`violations` count, so the gate proof does not depend on a human reading a log.

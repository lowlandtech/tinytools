## Outcome

`LowlandTech.TinyTools` ships only runtime types and runtime dependencies, so consumers do not inherit a mocking library or public test scaffolding.

## Acceptance criteria

- [x] UAC01: The packed nuspec declares no `Moq` dependency for any target framework.
- [x] UAC02: `LoggerExtensions` and `WhenTestingFor<T>` are absent from the shipped assembly and remain available to tests from `src/infrastructure`.
- [x] UAC03: The library project contains no `Moq` package reference and no `global using Moq`.
- [x] UAC04: A reflection fact over the shipped assembly asserts that no test-only type is public.
- [x] UAC05: The suite still passes on `net8.0`, `net9.0` and `net10.0` with the relocated helpers.
- [x] UAC06: Evidence records the packed dependency list per target framework before and after, and the readme's dependency statement matches the result.

## Scenario contract

Add SPEC3310/US01. Given reflects over the library assembly and inspects its public types, When the assembly is enumerated, Then facts assert that no test-only type is exported. The packaging proof is `dotnet pack` plus nuspec inspection recorded as evidence, not a unit test.

Two pre-existing `netstandard2.1` build breaks surfaced while packing, and both were mine from earlier product work in this run: `ArgumentNullException.ThrowIfNull` in `Compile` and `catch (RegexParseException)` in the `match` helper. That was not visible before because the solution build only ever builds the `net10.0` consumption path.

The readme now states the runtime dependency list per target framework and says explicitly that no mocking library or test scaffolding type ships, so the claim is checkable against the nuspec.

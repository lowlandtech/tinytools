## Outcome

The host can report what it would have refused - wrong credential, over budget, breaker open - without blocking anything, so protection can be evaluated before it is enforced.

## Problem

Rate limits and breakers are pointless to tune blind, and turning them on directly takes the surface down when the thresholds are wrong.

## Acceptance criteria

- [x] UAC01: Each request receives an immutable, request-scoped observation with its own trace identifier.
- [x] UAC02: The observation records the credential source as a bounded label (`api-key` or `none`), never the key.
- [x] UAC03: The observation records the decision the pipeline reached: `accepted` or `refused`.
- [x] UAC04: Observing changes nothing: a call the host would allow is still allowed with the same status.
- [x] UAC05: The observation records the verdict the enforcing policy would have given, so a refusal can be seen before it is enforced.
- [x] UAC06: A client-supplied identity header never becomes the recorded credential.
- [x] UAC07: A client-supplied forwarding address never becomes the recorded peer.
- [x] UAC08: Where the host already enforces, observing does not weaken it: an anonymous production call is still refused.
- [x] UAC09: A refusal is recorded as such, so an operator can see it without reading logs.
- [x] UAC10: Concurrent requests keep distinct observations - five calls produced five trace identifiers.
- [x] UAC11: The recorded fields are redacted: no key, no body, no template content.

## Scenario contract

Given observation mode, a fake clock, a counting store/executor and two concurrent request clients, When a request is over the SC04 limit, a store failure would open its breaker, and the other client succeeds, Then the named results are `WouldRateLimit`, `WouldOpenStoreBreaker`, and `ConcurrentObservationsIsolated` with unchanged response/business state, request IDs and redacted bounded fields. Keep host construction and calls visible in `SC11_ObservesProtectionWithoutEnforcing.cs`; one Fact per UAC01-UAC03.

## Divergence from the backend scope

The backend surface is `/api/plugins/{**path}` behind an account, device and IP model owned by the Auth
lane. Tinytools has one credential and seven template operations, and it deliberately refuses plugin
paths (`SPEC3315-US02-SC02`). Where the backend criterion depends on accounts or devices, this scope
requires the equivalent on this surface - credential scoping, provenance of the configured key, and
untrusted client headers - rather than inventing an account system here.

### Refinement, recorded

The original inventory asked for rate-limit and breaker observations, which belong to SC04 and do
not exist yet - and SC04 depends on this scope, so implementing them here would have meant inventing
SC04's mechanism inside SC11. It now delivers the observation context itself: trace, credential
source, peer, decision and the verdict enforcement would have given. When SC04 lands it records its
limit and breaker observations on the same object.

### What it costs

Nothing at request time beyond a bounded record: the middleware sets no status, adds no delay and
changes no result. The log holds 256 entries and no request content.

## Outcome

The repository pins its SDK to .NET 10 and its behaviour-test gate runs the tests CI actually
executes. Both hold, and the pull that broke one of them is undone with the reason recorded.

## What broke

The workspace SDK pin (`global.json`, commit `74715ac`) arrived with a second setting:

```json
"test": { "runner": "Microsoft.Testing.Platform" }
```

That setting switches `dotnet test` to the Microsoft Testing Platform argument model. This repository's
project is an xunit.v3 **library** with `xunit.runner.visualstudio` and `coverlet.collector`, and its CI
passes VSTest arguments (`--collect:"XPlat Code Coverage"`, `--results-directory`, `--filter
"FullyQualifiedName!~SPEC3309&FullyQualifiedName!~SPEC3327"`). Every one of those is rejected in the new
mode, so the runner printed its help and exited with `error: 1`, `total: 0` - a gate that reported
"Failed" without running a single test.

CI run `43783489302` failed on exactly that step. The two pushes before it were green.

## What was measured before deciding

| Probe | Result |
|---|---|
| SDK pin alone, through a complete .NET 10 host (10.0.404) | builds, 953 tests pass |
| `dotnet test --project … --filter-not-namespace <full namespace>` | does **not** exclude; needs the exact namespace, and these namespaces are four segments deep |
| `dotnet test --project … --filter-query '/*/((!*SPEC3309*)&(!*SPEC3327*))'` | **works**: 953 total, 0 failed |
| `dotnet test … --coverage` | `Unrecognized` even after adding `Microsoft.Testing.Extensions.CodeCoverage` 18.12.0, because the project is not an MTP test application (`OutputType` library, no `Microsoft.Testing.Platform`) |
| VSTest invocation with the runner switch removed | **953/953 pass**, coverage report written |
| `python eng/check-coverage.py <dir> --minimum 65` | `77.81% (2693/3461 lines)`, exit 0 |

So the argument model can be migrated in one afternoon, but the **coverage floor cannot**: extension
options never load for a non-MTP project, and the floor is a real quality gate at 65%. Dropping it to
adopt a runner setting is a worse trade than keeping the gate and pinning only the SDK - which is what
the workspace policy actually asks for (SDK `10.0.100`, `rollForward latestFeature`, prereleases
disabled). The `test.runner` line is not part of that policy text.

## Change

`global.json` keeps the SDK pin and drops the `test.runner` switch. Nothing else changed: the workflow,
the test project and the coverage floor are untouched.

## Recovery for the MTP migration, if it is wanted

1. Make the test project an MTP application: `OutputType Exe`, `Microsoft.Testing.Platform.MSBuild`,
   drop `xunit.runner.visualstudio`.
2. Replace `--filter "FullyQualifiedName!~…"` with `--filter-query '/*/((!*SPEC3309*)&(!*SPEC3327*))'`
   (verified working today).
3. Replace `--collect:"XPlat Code Coverage"` with the CodeCoverage extension's
   `--coverage --coverage-output-format cobertura`, and confirm `eng/check-coverage.py` still finds
   `**/coverage.cobertura.xml`.
4. Re-point the floor at the new report path and prove the gate fails when coverage drops.

That is a scoped workitem, not a config line, which is why it is not done here.

## Outcome

Control-flow rendering preserves source line boundaries after closing blocks and produces deterministic LF output on every supported operating system.

- [x] UAC01: Rendering `before\n@if (Context.A == 1) {\nmid\n}\nafter` with `A == 1` returns exactly `before\nmid\nafter`.
- [x] UAC02: Two adjacent true `@if` blocks with `one` and `two` bodies render exactly `one\ntwo` with one separator newline.
- [x] UAC03: A blank source line after a closing block is preserved; the premium example renders `Premium.\n\nItems:` at the corresponding boundary.
- [x] UAC04: Equivalent LF and CRLF input render identical canonical LF output on Windows and Linux.

## Refinement evidence

The reported reproducible failure is `Render("before\n@if (Context.A == 1) {\nmid\n}\nafter")` returning `before\r\nmidafter` on Windows; adjacent `@if` blocks return `onetwo`, while `@foreach` retains a separator. `TinyTemplateEngine.ProcessControlFlow` normalizes input line endings but plain lines use `AppendLine` and block results use `Append`, causing both the lost boundary and platform-dependent newlines. M1-003 is a dependency so this scenario uses the user's required visible Given/When test format. No implementation or test execution is claimed.

## Evidence
Root cause confirmed in `src/lib/Core/TinyTemplateEngine.cs`: `ProcessControlFlow` appended plain lines with `AppendLine` (host newline) while block results were appended with no separator at all, and a block's body text was re-joined without the line break that had closed it. The two bugs compounded into `before\r\nmidafter` for a block in the middle of a template.

The fix at `423c0ba`:

- a block body is rejoined by a single `BlockText` helper that terminates a non-empty body with the line break the closing brace had, so a blank line at the end of a loop body survives and an `@if` body keeps the boundary that follows it;
- plain lines are emitted with the canonical `\n` instead of `AppendLine`, so the output no longer depends on the host platform;
- a block appends a separator only when it rendered text without one and more source follows, and an empty block adds nothing.

The scenario `SPEC3300/US12.BlockOutputBoundaries/SC01_PreservesBlockLineBoundaries` captures five cases through the story `BlockOutputUseCase`:

| UAC | Input (via public `Render`) | Observed |
|---|---|---|
| 01 | `before\n@if (Context.A == 1) {\nmid\n}\nafter` | `before\nmid\nafter` |
| 02 | two adjacent true `@if` blocks | `one\ntwo` |
| 03 | `Premium.\n@if (Context.A == 2) {\n}\n\nItems:` with a false condition | `Premium.\n\nItems:` |
| 04 | the same template with LF and with CRLF | both render the identical LF string |
| 05 | nested `@if` around `@foreach` | `start\nouter\n- a\n- b\nend\nfinish` |

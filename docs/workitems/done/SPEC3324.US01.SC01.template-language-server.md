## Outcome

Editors get diagnostics, completion and preview for `.tmpl` files from one protocol server, instead of a Visual Studio-only extension that this repository cannot verify.

## Problem

SPEC3306-US01-SC01 is blocked: a VSIX needs the Visual Studio SDK, a VS test host and would fail every CI leg. The same capabilities are reachable through a language server that any editor can host, and the engine already exposes `ValidateSyntax` with line/column diagnostics to power it.

## Contract decisions (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Protocol scope | LSP 3.17 over stdio: `textDocument/publishDiagnostics`, `completion` for `${Context.` paths and helper names, and a `workspace/executeCommand` preview that renders the current buffer |
| Transport | stdio only in this item; sockets and named pipes stay out so the server runs inside any editor host |
| Model source | the model type is declared in `.editorconfig`/plugin metadata, mirroring SPEC3323, so completion knows which members exist |
| Testing | the protocol loop is exercised through an in-memory stream pair, so CI can prove behavior without an editor |
| Relationship to the VSIX | the extension becomes a thin shell owned by a lane that packages Visual Studio tooling; this item delivers the server it hosts |

## Acceptance criteria

- [x] UAC01: An `initialize`/`initialized` handshake over the in-memory stream pair completes and advertises the server capabilities.
- [x] UAC02: `textDocument/didOpen` on a template with an `@else` and no `@if` publishes a diagnostic carrying code `TS007` and a one-based position.
- [x] UAC03: Completion after `${Context.` returns the declared model's members and excludes unrelated ones.
- [x] UAC04: Completion for a pipe helper name returns the registered helper names and no duplicates.
- [x] UAC05: The preview command returns the rendered text for the current buffer revision, and a superseded request never overwrites a newer result.

## Scenario contract

Scenario `src/test/SPEC3324.LanguageServer/US01.Protocol/SC01_ServesEditorRequests.cs` drives the server through a loopback stream pair and asserts captured diagnostics, completion items and preview text.

## Evidence

Checkpoint after this change. `src/lsp` is a `net10.0` console that speaks LSP 3.17 over stdio and
reuses the engine this repository already ships.

- `JsonRpcChannel` frames messages with `Content-Length` and reads the stream as **bytes**, not text:
  the header counts bytes, so a text reader both miscounts non-ASCII bodies and swallows the next
  message. The first implementation used `StreamReader` for headers and the base stream for bodies and
  processed only the first request of a batch - the seven-fact scenario is what caught it.
- `TemplateLanguageServer` answers `initialize` (advertising `textDocumentSync`, a completion provider
  and the `tinytools.preview` command), `textDocument/didOpen`/`didChange` with
  `textDocument/publishDiagnostics` built from `ValidateSyntax`, `textDocument/completion` for model
  members and pipe helpers, and `workspace/executeCommand` for the preview.
- The host declares its model through `initializationOptions.modelType` (resolved from the loaded
  assemblies) or `initializationOptions.modelMembers`; the server has no project system, so it does
  not guess.
- `Program.cs` wires stdin/stdout and Ctrl+C, so the binary can be spawned by any editor.

Seven facts, driven through a buffered loopback pair with no sleeps:

| Criterion | Observed |
|---|---|
| UAC01 handshake | capabilities contain `tinytools.preview` |
| UAC02 diagnostic | an `@else` without `@if` publishes `TS007` |
| UAC06 position | reported at zero-based line 1, matching the source line 2 |
| UAC03 member completion | the declared model's `Name` and `Address` |
| UAC04 helper completion | the registered helper names, including `upper` |
| UAC05 preview | `Hello Ada` for the current buffer |
| UAC07 revision | the reply carries the revision the client asked for |

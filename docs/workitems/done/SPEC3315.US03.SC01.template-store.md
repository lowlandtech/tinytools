## Outcome

The templates feature is driven by an imported state store and HTTP client, so the page has one data path and the reducer can be tested without a browser.

## Acceptance criteria

- [x] UAC01: `TemplateState`, `TemplateActions`/messages, `TemplateReducer`, `TemplateEffects` and the HTTP `ITemplateService`/`ITemplateExecutor` clients are imported from `lowlandtech/develop/src/app/Features/Templates` and `Services/Http`, with behavior preserved.
- [x] UAC02: Reducer facts prove the documented transition for load, filter, select, edit, create, delete, validate and every failure message the foundry reducer handles.
- [x] UAC03: Effects facts prove each effect calls the documented endpoint and dispatches the documented success or failure message, against a stubbed HTTP handler.
- [x] UAC04: Every foundry behavior that depends on a surface this repository does not have (graph sync, session chat) is either ported or recorded in the deviation ledger with the named missing surface and its owning item.
- [x] UAC05: The state types carry no UI or `HttpClient` dependency; the page consumes state only.

## Scenario contract

Add SPEC3315/US03 with reducer facts that pass an action into `TemplateReducer.Reduce` and assert the resulting state, and effect facts that inject a recording handler and assert the request path plus the dispatched message. Keep Given/When visible: the action and the state are constructed in the fact or a named Given step, never inside the reducer.

## Outcome

`eng/smoke-package.ps1` verifies the published package on the SDK this repository pins, not on whatever
the machine happens to default to.

## The defect, found by audit

The script generates its consumer in the operating-system temp directory, which is outside the repository
and therefore outside `tinytools/global.json`. Coordinator-1 measured the consequence while auditing
`SPEC3337-US01-SC01`:

> the script runs dotnet from its generated temp consumer, outside tinytools/global.json; from that
> directory this machine selects SDK 11.0.100, not pinned 10.0.100
> (`20261125T154721766220Z-294b2c8f@coordinator-1`)

and confirmed the fix direction by hand:

> both green and intentional-red consumer runs also pass/fail as expected when I place a temporary .NET 10
> global.json above the generated consumer (selected SDK 10.0.404). The default script path still selects
> SDK 11 from OS temp, bypassing tinytools/global.json
> (`20261125T154850987490Z-4aa8ea7e@coordinator-1`)

A gate that verifies a package on a newer SDK than the repository requires is measuring the wrong thing,
and it would keep passing while a real net10-only break went unnoticed.

## Change

The script copies the repository's `global.json` into the generated consumer before restoring, so the
consumer resolves the pinned SDK. It also prints the SDK it selected, so the verdict names the runtime it
was measured on rather than assuming one:

```powershell
$globalJson = Join-Path $repositoryRoot 'global.json'
if (Test-Path $globalJson) { Copy-Item -Path $globalJson -Destination (Join-Path $consumer 'global.json') }

Push-Location $consumer
try { $selectedSdk = (& dotnet --version) } finally { Pop-Location }
Write-Host "Selected SDK in the consumer: $selectedSdk"
```

Nothing else changed: the assertions, the refusal to run without a packed version, the temp-consumer
cleanup and the deliberate absence from CI all stand.

## Verification

Green artifact:

```
pwsh eng/smoke-package.ps1
-> Selected SDK in the consumer: 10.0.404
   Verifying LowlandTech.TinyTools 2026.10.8 from D:/lowlandtech/packages
   single write                                           renders=1 expected=1
   staged write, 120 ms pause (inside the settle window)  renders=1 expected=1
   staged write, 400 ms pause (past the settle window)    renders=2 expected=2
   unrelated file change                                  renders=0 expected=0
   RESULT: PASS
```

Intentional-red artifact:

```
pwsh eng/smoke-package.ps1 -Version 2026.10.6
-> Selected SDK in the consumer: 10.0.404
   RESULT: FAIL
   The published package 2026.10.6 failed its consumer smoke with exit code 1.
```

So the pin is honoured **and** the gate still discriminates: it passes the corrected artifact and fails the
one that carries the watcher defect. Before the change the same runs selected `11.0.100`.

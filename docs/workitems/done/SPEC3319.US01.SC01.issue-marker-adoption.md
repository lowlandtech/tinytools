## Outcome

`eng/workitems.py --dry-run` manages this repository's issues instead of refusing them, so a future
closure can be reconciled by the shared tool rather than by hand.

## Problem

After SPEC3318 removed the 19 RMP021 documents, the tool got past the roadmap contract and stopped on

    Unmarked/conflicting issue identity: SPEC3305-US02-SC01

`plan_units` looks for `<!-- workitem:<scope> -->` in an issue body, and when no issue carries the
marker it refuses to adopt an issue whose title merely contains the scope. All 38 managed issues
predate the marker, so the tool could not run at all. That is why every closure in this lane today
needed hand-made GitHub state changes, and why no mirror completeness could be claimed.

## Contract (lane-owned, resolved before implementation)

| Question | Decision |
|---|---|
| Marker form | `<!-- workitem:<scope> -->` as the first line of the issue body, matching what `plan_units` searches for |
| Body preservation | the existing body is appended unchanged; only the marker line is prepended, so no issue history is lost |
| Scope source | the sole board's Issue cell, so the mapping is derived from the roadmap rather than retyped |
| Idempotence | an issue already carrying the marker is skipped, so re-running is safe |
| Not claimed | `--apply`. Applying replaces each body with the tool's generated content, which is a separate decision about what a managed issue body should contain |

## Acceptance criteria

- [x] UAC01: Every managed issue carries the marker for its board scope, and re-running the adoption skips them.
- [x] UAC02: `eng/workitems.py --dry-run` returns `ok: true` with 38 items, an action per scope and no diagnostics.
- [x] UAC03: Issue bodies keep their previous content below the marker; spot-checked on the first issue and preserved by construction for the rest.

## Scenario contract

No product behaviour; the evidence is the tool output before and after, plus the marker state of the
issues.

## Evidence

Before: `{"ok": false, "error": "Unmarked/conflicting issue identity: SPEC3305-US02-SC01"}`.

Action: 37 issues marked, 1 skipped (already marked), 38 total, bodies preserved below the marker.

After:

    {"ok": true, "repo": "lowlandtech/tinytools", "items": 38, "applied": false,
     "unchanged": 0, "actions": [ ... 38 entries ... ], "diagnostics": []}

Every board scope maps to its issue number in that output, so the roadmap, the sources and the
managed issues now agree by construction instead of by inspection.

Not claimed: `--apply`, which would rewrite issue bodies with generated content, and any mirror
completeness statement that depends on it.
